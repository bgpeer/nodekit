# 15. 证书管理

> **`15 证书管理`**：证书是全机共用的地基——节点、订阅服务、nginx 443、AdGuard 的 DoT 全指着
> 同一个 `/etc/ssl/sb/acme.crt`，它一坏就是**全部一起挂**，而且日志里只有一句「连不上」。
> 所以这个菜单先把状况摆出来（域名 / 颁发机构 / 剩多少天 / 续期模式 / 覆盖了哪些域名），
> 有问题的环节红字点名，再给四个按钮：
>
> | 按钮 | 什么时候用 |
> |---|---|
> | **1 安装证书** | 还没有证书，或想把手上的单域名证书**升级成泛域名**（Emby 要共用就得是泛域名） |
> | **2 更换域名** | 换掉你自己的域名：证书、两个核心的入站、nginx、每条分享链接、订阅、Emby 一次改完 |
> | **3 强制重签** | 到期前后、或面板报了「盖不住节点域名」「私钥对不上」这类硬伤 |
> | **4 Emby 证书** | 跟节点**共用一张**还是**各用各的**，进去两边随时切换（装了 Emby 才显示） |
> | **5 清理旧证书** | acme.sh 里换域名留下的旧记录会在半夜把节点证书覆盖掉，这里列出来点名删 |
>
> 要点是**换证书之前一定先验**
> （解析得开 / 盖得住节点域名 / 没过期 / 私钥配对），四条任一条不过就丢弃新的、
> 现有证书一个字节不动。
>
> ⚠ 最小化的 Debian / GCE 镜像**可能压根不带 `cron` 包**。它一缺，acme.sh 的每日续期和
> 「内核每月自动更新」会从第一天起就没在跑，而且悄无声息——acme.sh 发现没有 `crontab`
> 只打一行警告就继续，装完一切看着正常，直到 90 天后证书到期全线挂掉。所以 `cron` 现在进了
> 安装依赖清单，装完顺手 `systemctl enable --now`。
>
> ⚠ **重签/换证书会掐断你的 SSH**（如果你是挂着本机代理在管这台机的）：最后一步要
> `systemctl restart sing-box / xray`，代理链路一断 SSH 跟着断。所以它跟菜单 19「更新核心」
> 一样**派到独立会话里跑**（脱离控制终端，SIGHUP 打不到它），断线也会在服务端跑完；
> 重连后 `tail /var/log/bgpeer-certfix.log` 看结果即可。
>
> 面板顶部会在证书**剩 10 天以内或已过期**时打一行红字提醒。安装/增量添加时也会顺手把
> `reloadcmd` 补进 acme.sh —— 早期版本装的机器可能压根没记过这条 hook。

- **证书自动续签**：走域名真证书时用 acme.sh 签发，acme.sh 会装每日 cron 自动续期（约 60 天一次），
  续期后自动重启 sing-box / xray（有 nginx 顺带 reload）使新证书生效，无需手动干预

证书是全机共用的一块地基：节点（sing-box/xray）、订阅服务（xy-sub）、nginx 443、AdGuard 的 DoT
全指着 `/etc/ssl/sb/acme.crt`。它一过期就是**全部一起挂**，而且谁都不会报「证书过期」，
只会「连不上」。所以这个面板把每一环都查出来摆在眼前：

```
  域名:      example.com   泛域名
  颁发机构:  Let's Encrypt
  有效期:    还剩 61 天到期          ← >30 绿 / 7-30 黄 / <7 红
  续期模式:  自动   DNS-01 Cloudflare（可签泛域名，不占端口）
  覆盖域名:  example.com, *.example.com
  正在使用:  sing-box, xray, 订阅服务, nginx, AdGuard
  Emby 证书: media.example.com   还剩 61 天   已被本证书覆盖
```

真正会让证书悄悄过期的是这两环，缺了会红字点名：

| 检查项 | 缺了会怎样 |
|---|---|
| crontab 里有没有 acme.sh 的每日续期任务 | 到期根本不会自动重签 |
| acme.sh 记没记 `reloadcmd` | 重签了也没用——节点/订阅捏着启动时读进内存的旧证书 |
| 私钥和证书配不配对 | 握手直接失败，但文件看着一切正常、日期也没问题 |
| **盖不盖得住节点正在用的域名** | 所有吃证书的节点被客户端拒绝（`tls: bad certificate`），**而 reality 照常通** |

最后一条是最难认的一种故障：现象是「随机几个节点坏了、另几个好好的」，没人会往证书上想。
它最阴的一条来路是**换过域名的机器**：acme.sh 的 `--install-cert` 会把「装到哪个文件、
装完跑什么」存进**那个域名自己的记录**里，往后每次自动续期都照做。换域名时新证书装到了
同一个路径，可**旧域名那条记录没人删**——它的每日 cron 照常续期，续完就把节点正在用的证书
覆盖成旧域名那张，还顺手按存着的 `reloadcmd` 重启了核心。域名有泛解析（`*.域名`）的话，
旧域名照样验证得过，所以它能一直成功地捣乱。**发作在半夜、你什么都没做**，第二天发现
一半节点连不上、reality 好好的。

所以面板会额外查一条：**acme.sh 里还有谁也往这个文件装证书**，有就红字点名；
『3 强制重签』会在重签**之前**先把它们的续期跟踪撤掉（`--remove`，只是不再跟踪、不删文件）
——不先撤掉的话，这次重签出来的证书过几个小时又被盖回去，而那时你已经不在看了。

**5 清理旧证书** 把 acme.sh 里所有域名记录列出来，标明每一张是干什么用的：

| 标记 | 含义 | 可删 |
|---|---|---|
| 节点在用 / Emby 在用 / 别处在用 | 有主 | 否，手动点名也会被拒绝 |
| **抢占中** | 装到节点的证书文件、却不是节点域名 —— 每次续期都会把节点的证书覆盖掉 | **强烈建议删** |
| 没人用 | 装到的文件已经不在、或压根没配过安装路径 | 是 |

判「是不是节点那张」用的是**真正的覆盖判定**，不是把星号去掉再比字符串——`*.a.com` 并
**不**覆盖 `a.com` 本身，那种记录多半是 Emby 的（它服务的是 `<子域>.a.com`）。
删除默认只 `--remove`（停止自动续期），磁盘上的证书文件另问一次才删。删掉「抢占中」的
之后会提醒去点『3 强制重签』，把节点的证书重签回来。

另外换证书前会**先比对节点正在用的域名**：盖不住就丢弃新证书、现有的一个字节不动；
签发时也会把节点域名**无条件带进要签的名字里**。

**同一道闸也装在自建 DNS（菜单 13）那侧。** `/etc/ssl/sb/acme.crt` 有两个脚本会写：
装 / 撤 DoT 的泛域名证书时，adguard 那边也 `--install-cert` 进同一个文件。它取域名用的是
`sub.host`，而节点的真相在 `state.json`——换过域名、手工改过、订阅还没重生成，两者都可能漂。
所以那边导完证书也要验一次盖不盖得住节点域名，不合格就**先把 acme 记录改回节点域名**
（免得下次自动续期又来一遍）、**再还原证书文件**（顺序不能反，`--install-cert` 自己也写这两个
文件）、重启回吃证书的服务。media-stack 那侧只读这个文件、不写，不受影响。

**重装节点不会再把泛域名静默降级成单域名。** 签证书有两种验证方式，而 **HTTP-01
根本签不出泛域名**（Let's Encrypt 的硬规定，泛域名只能走 DNS-01）——而节点安装/重装
走的正是 HTTP-01 那条路。所以以前只要重装一次，`*.域名` 就没了，**已经合并好的 Emby
当场被拆回两张证书、两条续期链，全程不吭一声**，等你发现已是几周之后。

现在重签之前先问一句「这台机本来该不该有泛域名」，三个线索任一成立就算：`cert.json`
记着上次装的是泛域名 / 磁盘上现有的那张就是泛域名 / Emby 正跟节点共用着它。是的话：

- acme.sh 里存着 Cloudflare 凭据 → **改走 DNS-01 把 `域名 + *.域名` 签回来**，
  Emby 的软链指向这个文件，泛域名保住就不会断
- 没有凭据、只能降级 → **爆黄字说清楚**丢了什么、会坏什么、装完去哪儿补，绝不静默

本来就不需要泛域名的机器照旧走 HTTP-01，不会平白把所有人改成 DNS-01。

**顺带修了 `cert_covers` 的判定。** 它原来是拿 `openssl x509 -text` 的**整段文本做子串
匹配**，两头都会错：一张纯 `*.a.com` 的证书，文本里含有 `a.com` 这串字符，于是被当成
「盖得住 a.com」——可**泛域名不顶自己**，装上去裸域名直接握手失败；反过来 `b.a.com`
的证书也会被误判成盖得住 `a.com`。现在走 SAN 列表 + 和客户端一致的覆盖判定。

**1 安装证书** 可以在**没有任何节点的时候**先装。两种验证方式：`HTTP-01` 只签单域名、
要求域名已解析到本机（会先查一遍再动手）；`DNS-01` 用 Cloudflare Token 签 `*.域名`
泛域名，不占端口、子域名和 Emby 都能共用（acme.sh 存过 Token 就不用再填）。

**装上去之前一定先验**，四条全过才碰现有证书：文件解析得开 / 覆盖得到这个域名（泛域名只顶一级）/
没过期 / **私钥和证书配对**。任一条不过就丢弃新的、现有证书一个字节不动。验过了才备份、
换上、记 `reloadcmd`、补续期任务、让吃证书的服务重读；中途出错自动还原并重启回来。

**状态两边同步**：证书的事实来源是 `/etc/bgpeer/cert.json`（老机器升级上来会从磁盘上的
证书自动推一份）。先在这里装好证书，再去『1 节点安装』，向导会直接认出来：

```
  ✓ 检测到已安装证书：example.com（泛域名）   Let's Encrypt   还剩 61 天到期
    节点直接用它，不会重新申请。回车即用这个域名；想换别的就直接输。
```

**已经装着单域名证书时，`1 安装证书` 走的是「升级成泛域名」这条路。** 从单域名升到泛域名
**不是重签**——验证方式要从 HTTP-01 换成 DNS-01，签的名字也多了 `*.域名`。走『3 强制重签』
沿用的是 acme.sh 记录里原来那套，永远签不出泛域名；没有这条路，装了单域名证书的机器
就没法让 Emby 共用。升级会把 Emby 的子域一并签进去（同域自动去重），校验时**每一个
域名都要盖住**才换上去。

签发同样是**转后台**跑的（要重启吃证书的服务），SSH 断了照样完成。

**2 更换域名**：把**你自己的**域名换掉 —— 客户端连的那个、证书签的那个。
不是 reality 借用的伪装站（那个在菜单 4）。

域名散落在这台机的九个地方，漏掉任何一处的后果都长得一样：某天一半节点连不上，
而日志里只有一句「连不上」。所以这件事只能一次做完，不能手工挪：

| 落点 | 漏了会怎样 |
|---|---|
| `state.json` 的 `domain`/`host` | 下次进安装向导还是旧域名；所有读它的功能一起漂 |
| `sub.host` | 订阅 URL、GitHub 中转、自建 DNS 的 DoH 地址全指着旧域名 |
| `xy-nodes.txt` 里每条分享链接 | 节点连的还是旧域名 |
| sing-box 入站的 `tls.server_name` | 客户端 SNI 对不上 |
| xray 的 `serverName` / `xhttpSettings.host` | 同上 |
| nginx 三处 `server_name` | 443 伪装站和 ws 反代收到请求不认 |
| `/etc/ssl/sb/acme.crt` | `tls: bad certificate`，而 reality 照常通 |
| **acme.sh 里旧域名那条记录** | **它的每日 cron 半夜把证书覆盖回旧域名那张** |
| Emby 的 `.env` + nginx + 证书 | Emby 那半边还留在旧域名上 |

⚠ **最容易写错的一处**：reality 的 `sni=` 是**借用的第三方站**（`s0.awsstatic.com` 之类），
跟你自己的域名没有半点关系。跟着换 = reality 全挂，而且是静默的握手失败。
所以带 `security=reality` 的链接只动 `@主机名`、query 一个字不碰，两个核心的配置里
也整块跳过 reality 入站。

**顺序是有讲究的，反了会出人命**：

```
1. 先改两个核心的配置 + nginx，各自跑内核自带的校验
   ← 纯本地、可回滚，而且这时候服务还没重启，写坏了也没有任何东西是坏的
2. 校验全过了才去签证书
   ← 反过来的话：证书已经换成新域名、配置却因为校验不过回滚回了旧域名，
     所有吃证书的节点当场被客户端拒绝，而 reality 照常通
3. 证书也拿到了，才动 state.json / sub.host / 分享链接 / 订阅
4. 最后撤掉旧域名的 acme 记录再重启
```

任一步失败都**整体回滚**，包括前面已经改好的部分。

**「盖得住」不等于「能用」。** 现有证书如果名字上已经盖得住新域名，流程会跳过重签
省掉一次签发——但跳过之前**一定**要把那张证书本身验一遍：它可能只剩三天到期，也可能是
上次签发中断留下的「新证书配旧私钥」（文件看着一切正常、日期也没问题，握手直接失败）。
不验就跳过，等于把这两种毛病原样带进新域名。不可用会**爆红**说明是哪一条不过，
然后整体回滚，并指路先去『3 强制重签』。签发那条路走完之后，还会拿**现役的**那张
再验一遍才算数——`cert_install_apply` 验的是临时文件，换上去之后没人再看一眼。

**动手之前先把 DNS 做好，否则证书根本签不出来。** 问域名之前就会把两条前置条件
摆出来（带上本机公网 IP，省得你另开一个窗口去查）：

| 要做的 | 不做会怎样 |
|---|---|
| **① 新域名的 A 记录指向本机公网 IP** | 证书签得出来，但客户端连不上 —— 等于把所有节点一次性打死 |
| **② 域名托管在 Cloudflare（在 CF 的区域里）** | 泛域名证书走 DNS-01，acme 要用 CF 的 API 往区域里写 TXT 验证记录；域名不在 CF 名下，Token 权限再对也签不出来 |

DNS 有缓存，改完**等生效**再来。填完域名会实地解析一次比对本机 IP，不匹配会红字
说清楚查到的是什么、本机是什么，并给出自查命令；**走 CF 小黄云代理会查到 CF 的 IP，
节点不能套 CF，得先改成「仅 DNS」**。

确认框里会把这次要动的文件逐个列出来，以及**不会**动什么（借用站、端口、uuid、
密码、路径、short-id，还有 CDN 那几个走自己域名的节点）。

**确认要完整打出 `yes`**，不接受 `y`。这件事会动到全机每一样吃证书的东西，不该靠手滑触发。

**证书是全机共用的地基，吃它的每一样东西对外报的地址都要跟着改。** 确认框里先黄字
列一遍有哪些，换完再把每一条的**新值**打出来，照着去各自的配置里改：

| 跟着变的 | 去哪儿看新值 |
|---|---|
| 订阅地址 | 面板 `2`　⚠ host 变了，客户端要**重新导入**，不是刷新 |
| 节点链接 | 面板 `2`　单条分享链接发给别人过的，要重发 |
| 自建 DNS 的 DoH | 面板 `13`　手机「专用DNS」/ 路由器里填的那个要改 |
| GitHub 中转 | 面板 `14`　订阅里自动换好了；手工引用过的要改 |
| Emby | 面板 `16`　App / 客户端里存的地址要改 |

没开的功能不会列出来，免得你去找一个不存在的东西。

节点本身的端口/uuid/密码一个字节没动，所以重新导入之后老节点照常能用。

> **为什么不干脆按原设置重装一遍？** 重装会把每个节点的端口、UUID、密码**和订阅 token
> 全部重新生成**——换个域名而已，所有客户端都要重新导入、所有单条分享链接作废、
> 聚合的成员机也得跟着改。外科手术式改写贵在写和测，但换完客户端刷一次订阅就行。

**4 Emby 证书**：自建 Emby 原本自己签一张 `*.域名`（装在 `/etc/nginx/certs/`），
跟节点那张各自 90 天、各自续期——等于把「证书过期全挂」的风险配了两份，而且 Emby 那条
续期链断了不会有人发现（平时不看、真挂了才知道）。合并后两张变一张。

判断能不能合并要看**泛域名**：Emby 对外是 `<子域>.<域名>`（`emby.` / `mw.` 等好几个），
所以节点证书必须是 `*.域名` 才顶得住。裸域证书盖不住任何子域名——面板会如实区分
「本证书已能顶替它」和「另一张，独立续期」，顶不住时会指路先用 DNS-01 重签一张泛域名的。

合并的做法是把 `/etc/nginx/certs/<域名>.crt|key` 换成**指向节点证书的软链**，
Emby 的 nginx 配置一个字不动——这样以后重跑 Emby 安装也不会把它改回去。
顺带撤掉 acme.sh 对 `*.域名` 的单独续期记录（只是不再跟踪，不删文件），
否则它续完会把软链覆盖成实体文件、悄无声息退回两张。节点证书的 `reloadcmd` 本来就
reload nginx，所以合并后 Emby 自动跟着吃到新证书。原证书备份成 `.bak`，随时能还原。
换软链后先跑 `nginx -t`，不过就整个还原并 reload 回去。

进去是**一屏两向选择**，不是盲切换。原来这里按下去它自己决定合并还是拆开，
而合并不了的时候只丢一句「顶替不了」就退出来 —— 你看不到当前处在哪一边、
能不能到另一边、不能是因为什么。现在两个方向并排摆着，各自标着状态和原因：

```
  当前:      各用各的（两张证书、两条续期链）
```
