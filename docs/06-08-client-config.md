# 6 / 7 / 8. mihomo / sing-box / 小火箭配置

- **修改配置**：编辑器直接改成品配置文件
- **修改订阅**：查看当前订阅 / 换 token（换链接不动配置）
- **更新配置**：用作者模板或**自定义模板**重新生成。会**先校验再生效**：成功显示
  `✅ 更新成功`；若模板改坏了（JSON/YAML 语法错、缺关键段）显示 `❌ 更新失败` 并打印
  具体语法错误，**自动保留原来能用的配置、不会把坏的推给客户端**。
  （只验语法，不用服务器内核对客户端配置做语义校验——避免客户端/服务器内核版本不同、
  模板里 `dns.optimistic` 等字段被误判失败。）
- **自定义模板链接（添加 / 更换 / 删除）**：把你放在 gist / GitHub 上、占位符一致的模板拉进来映射节点。
  已设过链接再进来会给 **`1 更换` / `2 删除` / `0 返回`**；删除即改回作者模板，并可当场用作者模板重新生成一次配置
- **自动更新（默认开）**：每天**北京时间 03:20** 按当前生效的模板（作者 / 自定义，跟「当前生效」那行一致）重新生成，拉到作者模板 / 你模板的最新改动；不动节点、不换 token、不重启任何服务，失败自动保留原配置。三个格式各自开关。用「修改配置」手改过的格式会**暂停**自动更新（免得被覆盖），之后重新生成过一次配置就自动恢复，也可在菜单里手动恢复。日志：`/var/log/bgpeer-cfgupdate.log`

> 重装节点会刷新三条订阅的 token；只更新脚本或更新配置不换 token。
> sing-box 订阅按模板的**紧凑格式**输出（每个节点/策略组/规则一行一个），不会展开成逐行大 JSON。

## 应用新配置：sing-box 热重载，xray 重启

改完配置（smux、屏蔽中国、BT 屏蔽、证书续期等）要让核心认账，脚本对两个核心区别对待：

- **sing-box 发 SIGHUP 热重载**。它收到信号会**先自己 check 一遍新配置，不过就只记一行错、
  继续用旧配置跑**。同一份坏配置，热重载顶多是「没生效」，`restart` 则是进程直接退出、
  再被 `Restart=on-failure` 拖进重启循环——节点全掉。
- **xray 只能 restart**。它的 `main/run.go` 只监听了 SIGINT / SIGTERM，不认 SIGHUP。

老版本装出来的 unit 没有 `ExecReload`，脚本会在第一次需要时自动补上并 `daemon-reload`，
补不了就照常退回 restart，不会因此把「应用配置」这件事搞砸。

> 别误会热重载能保连接：sing-box 收到 SIGHUP 还是会关掉旧实例再重建，**现有连接照样断**。
> 省掉的是进程重建、以及「新配置有错就没得救」这两件事。

## 自定义模板 & 锚点

你可以把**自己的配置模板**放到 gist / GitHub raw，脚本按锚点把节点和国家随机组注入进去。
好处：**既能在模板里手写自己的静态节点，又能把成品配置直接托管到服务器保存**；
本仓库的作者模板既是参考，也是首次搭建的人开箱即用的配置。

**三个作者模板（点开直接看）**：

| 客户端 | 模板文件 |
|--------|----------|
| mihomo / Clash | [`sub-template.yaml`](https://github.com/bgpeer/nodekit/blob/main/sub-template.yaml) |
| sing-box | [`subbox-template.json`](https://github.com/bgpeer/nodekit/blob/main/subbox-template.json) |
| Shadowrocket（小火箭）| [`shadowrocket-template.conf`](https://github.com/bgpeer/nodekit/blob/main/shadowrocket-template.conf) |

> **sing-box 模板要 1.15+，1.14 装不上**（这是**有意的**，不是待修的 bug）。
> 卡住的只有 `experimental.cache_file` 的 `buffer_size` / `flush_interval` 两个字段——
> sing-box 的配置解码开了 `DisallowUnknownFields`，**未知字段不是忽略而是直接启动失败**，
> 1.14.1 上报 `json: unknown field "buffer_size"`，整份配置加载不了。实测去掉这两个
> 1.14.1 就能过，也就是说整份模板只卡在这两处。
>
> 换句话说：**看到 1.14 报这个错，别去删那两个字段**——要么升到 1.15，要么自己 fork 一份模板。
>
> 另外 TUN 段**故意不写 `mtu`**。sing-box 的默认值是分平台的（Network Extension 4064、
> Android 9000、桌面 65535），一份订阅喂三个平台，写死任何一个数都会坑到另外两个；
> 尤其别写 9000——源码注释明说 iOS 上超过 4064 性能会显著下降。

### 三个锚点（三格式同名，各按自己语法渲染）

| 锚点 | 作用 | 展开成 | 放哪 |
|------|------|--------|------|
| `_NOD_` | **建节点** | 你 VPS 的真实节点 | 独占一行（mihomo `proxies:` 段 / sing-box `outbounds` / 小火箭 `[Proxy]` 段） |
| `_GRP_` | **建国家策略组** | 各国 url-test 随机组的**定义** | 独占一行（mihomo `proxy-groups:` 段 / sing-box `outbounds` / 小火箭 `[Proxy Group]` 段） |
| `_NAM_` | **引用国家组名** | 建好的国家组**名字清单** | **写在列表行内**（主选择组 / 服务组的 proxies·outbounds 里，可放多处） |

> 顺序依赖：必须先有 `_GRP_` 把组**造出来**，`_NAM_` 才有组名可引用；
> 只写 `_NAM_` 不写 `_GRP_` → 引用了不存在的组 → 客户端报错/起不来。

> **老锚点名仍然认**：以前叫 `__XY_NODES__` / `__XY_GROUPS__` / `__XY_NAMES__`，
> 现在统一成 `_` + 三个大写字母 + `_` 的短写法。脚本拉到模板后会先把老名字换成新名字，
> 所以你手上按老模板改的**自定义模板不用动**，两种名字可以混着写。新写模板请用短的。

### 国家随机分组是怎么来的

- 脚本扫描**全部节点名**（`_NOD_` 注入的订阅节点 **＋** 你手写进模板的静态节点），
  按**旗子 / 关键词**（如 `🇯🇵`、`JP`、`日本`、`Tokyo`）归国；
- 某国**≥2 个**节点才建该国随机组（`1` 个不建）；剩下没归入任何国家的进「🎲其他随机」；
  `🇺🇲` 自动归一到 `🇺🇸`；一个国家都没有则整段不建。
- **mihomo** 用 `filter`+`include-all`：客户端按正则**自动收拢**匹配节点（连你机场订阅合并进来的同国节点也会进组）；
- **sing-box / 小火箭** 没有 filter：由脚本**算好每国成员显式列进去**。
- **中国节点**（名字带 `🇨🇳` / 独立的 `CN`、`cn` / `中国大陆`，且不带其它国家标记——
  `🇨🇳台湾`、`深港`中转、`CN2` 线路都不算）**不进出国用的组**：收进「🎯直连」（可手选单节点）
  和一个隐藏的「🇨🇳中国随机」（用国内地址测速），并从 🌍全球加速 / ♻️全部随机 / 🎲其他随机 /
  各服务组里剔除。有 1 个就生效，不受「≥2 个」的门槛限制；**全是中国节点**时不剔除（不然出国组就空了）。
  小火箭的 `policy-regex-filter=.*` 在有中国节点时会换成显式列出的非中国节点。

#### 想在模板里自己写国家组？同名即接管（**三种格式都一样**）

脚本生成前会先扫一遍模板里已有的组名，**同名的就不再自动生成**，让你写的那个说了算：

| 你在模板里写 | 脚本行为 |
|---|---|
| 什么都不写 | 照常生成 `🇺🇸美国随机`、`🇯🇵日本随机` 等 |
| `🇺🇸美国自动`（**不同名**） | 两个**并存**——你的 `🇺🇸美国自动` + 脚本的 `🇺🇸美国随机`，各管各的 |
| `🇺🇸美国随机`（**同名**） | **不再生成**，样式完全由你定；其他国家组不受影响 |

各格式扫描的位置：**mihomo** 扫 `proxy-groups:` 段；**sing-box** 扫 `outbounds` 里所有 `tag`；
**小火箭** 扫 `[Proxy Group]` 段。同名被跳过时，那个名字**仍会由 `_NAM_` 展开**——
引用会指向你模板里的同名组，位置和作用跟原来一致，不用额外改什么。

> **不同名时要注意**：`_NAM_` 只展开**脚本生成的**组名。你自己写的那个要出现在别的策略组里，
> 得**手动加进对应的列表**（mihomo 的 `proxies:` / sing-box 的 `outbounds` / 小火箭的组定义行）。

为什么要这样——重名不是「以某一个为准」的软覆盖，是**硬失败、客户端直接起不来**：

```
mihomo    ProxyGroup 🇺🇸美国随机: duplicate group name          → 配置加载失败
sing-box  FATAL decode config: duplicate outbound/endpoint tag  → 配置解析失败
```

### 放置规则（照着作者模板抄最稳）

- **块锚点**（`_NOD_` / `_GRP_`）：**各占一行**。顶格或缩进都行（生成器会整行替换、自带缩进，缩进不会把 YAML 弄乱）。YAML 里还可以写成列表项 `  - _NOD_`，前面那个 `- ` 会一起被替换掉——作者模板就是这么写的，好处是模板本身能当合法 YAML 解析。
- **行内锚点**（`_NAM_`）：写在 `[...]` 列表里。例：
  - mihomo：`proxies: ["♻️全部随机","_NAM_"]` → `["♻️全部随机","🇯🇵日本随机","🇺🇸美国随机"]`
  - sing-box：`"outbounds": ["♻️随机", "_NAM_:.*"]`
#### sing-box：可拆解的锚点（`outbounds` 里三种写法自由组合）

sing-box 的策略组成员由两件事拼成——**要不要列国家组名**、**要不要带节点名**。
两者各由一半语法控制，可以单独写、也可以合起来写：

| 写在 `"outbounds"` 里 | 国家组名 | 节点名 | 用途 |
|---|:---:|:---:|---|
| `_NAM_` | ✅ | ❌ | 只想列国家组，节点收进组里不铺开 |
| `<正则>`，例 `.*` | ❌ | ✅ | 只要节点、不要组（`♻️随机` 这种 urltest 池） |
| `_NAM_:<正则>` | ✅ | ✅ | 两个都要（作者模板 19 个 selector 组用的就是这个） |

正则匹配的是**节点名**，所以能筛：`🇺🇸|US` 只收美国节点，`.*` 收全部。

```jsonc
// 只列国家组
{"tag": "🌍代理",  "type": "selector", "outbounds": ["♻️随机", "_NAM_"]}
// 只收全部节点，不列组 —— urltest 池就该这样，列了组会把组和它的成员一起测
{"tag": "♻️随机",  "type": "urltest",  "outbounds": [".*"]}
// 两个都要
{"tag": "🎬TikTok","type": "selector", "outbounds": ["🌍代理", "♻️随机", "🎯直连", "_NAM_:.*"]}
// 裸正则也能筛：只要美国节点
{"tag": "🇺🇸美国专用","type":"urltest", "outbounds": ["🇺🇸|🇺🇲|US"]}
```

> **裸正则怎么跟字面 tag 名区分**：`"DIRECT"`、`"🎯直连"` 这些也是普通字符串，语法上跟正则
> 没区别。生成器的判法是——**先查这个字符串是不是已有出站**（模板自己定义的 tag ＋ 注入的
> 节点 ＋ 自动建的国家组），是就当字面量原样保留，不是才按正则去匹配节点名。
>
> 所以 tag 名写错一个字（比如 `🎯直連`）不会被静默当成正则丢掉：匹配不到节点时**保留字面量**
> 并打一条警告，sing-box 照常报 `outbound not found`，一眼能看出是哪里写错了。

> 机制核心：**检测到锚点才展开，漏写不报错、只是不生成**。就算忘了写 `_NOD_`，也只是不注入节点、模板原样拉上来，不会报错。

### 怎么用自定义模板

1. 进对应配置菜单（**5** mihomo / **6** sing-box / **7** 小火箭）→ **添加自定义模板链接**（填你 gist / GitHub 链接，文件页或 raw 都行）；
2. 再选 **更新配置 → 自定义模板** 重新生成（不动节点、不换订阅 token）。

> 💡 **GitHub 文件页链接直接贴就行**：浏览器里看文件时的地址（`https://github.com/.../blob/...`）和
> gist 页面地址（`https://gist.github.com/用户/ID`），脚本会自动换成原始文件链接（屏上会显示换成了什么）；
> 当然直接点 **Raw** 复制 `https://raw.githubusercontent.com/...` 也一样。多文件的 gist 请贴那个文件的 Raw 链接。
> 链接拉到的若还是网页（比如私有仓库），会报错并保留原配置，不会把网页当模板写进订阅。
>
> 更新配置每次都**实时重新拉取**你模板的最新版；GitHub raw 有约 5 分钟 CDN 缓存，改完模板等一两分钟再点更新。
