# 17. VPS线路检测

拉本仓库的 `vps-check.py` 跑一遍体检，纯 stdlib、无第三方依赖（`traceroute` 缺了会自己
apt/yum/apk 装）。两个按钮：

菜单进去先回显**上次本机检测的结果**（时间、IP、三网各走哪条骨干、IP 标记、黑名单），
没测过就写「还未检测过」——不用为了看一眼结论再等两分钟。结果落在
`/etc/bgpeer/vps-check.last.json`，只存本机的：外部 IP 检测查的是别人的 IP，
跟这台机器的线路无关，混进去会让人误以为是本机结论。

- **`1 本机IP检测`** —— 四节全查（下面 1~4），约 2 分钟。
- **`2 外部IP检测`** —— 输入任意 IPv4，查三样：那个 IP 的**画像**、**本机到它的链路**
  （TCP 握手 + 逐跳，做中转/落地链时看这个）、它的**黑名单**。约 20 秒。

  > **它的三网回程测不了**，这不是没做，是原理上做不到：traceroute 是从**发起方**
  > 往外探，在你这台机上跑，探到的永远是**你这台机**的出网路径，跟目标那台机怎么
  > 回中国无关。要测那台机的线路，SSH 上去跑一行就行（纯 stdlib，不装任何东西）：
  > `curl -fsSL https://raw.githubusercontent.com/bgpeer/nodekit/main/vps-check.py | python3`
  > ——结论那一节会把这行命令原样打出来。

  > **BGP 也查不出 CN2**，试过了。画像里的「上游/邻居」是 Cymru 的 peer 记录
  > （那个前缀的邻居 AS），本来指望里面出现 `AS4809`/`AS4134` 就能当 CN2 的证据——
  > 拿一台**确认走 CN2 GIA** 的机器（DMIT LA，`69.63.210.0/24`）实测，邻居只有
  > `AS2914 NTT` / `AS3257 GTT` / `AS137409`，**4809 和 4134 一个都没有**。
  > 原因：CN2 是私有电路、`59.43` 根本不在 BGP 全局表里，商家把出境流量交给哪条
  > 电路是**转发决策**，全局路由表看不见。所以这行只当**上游构成**看
  > （NTT/GTT/Cogent/HE 之类），不作线路判定。
  >
  > 不登录目标机还想摸它的中国线路，只剩一条路：**从国内侧测去程**（中国→目标）。
  > 而**你国内的那台电脑本身就是探针**，不用绕 VPS——绕了反而变成「国内→VPS」加
  > 「VPS→目标」两段，量的不是你要的那条。在**你自己电脑上**跑：
  >
  > ```
  > curl -fsSL https://raw.githubusercontent.com/bgpeer/nodekit/main/vps-check.py | python3 - --hops <目标IP>
  > ```
  >
  > 会列出逐跳并按骨干分类，末尾给「路径上的骨干」小结。Windows 没 python 就用
  > `tracert <目标IP>`，自己看有没有 `59.43` 段。
  >
  > **CN2 GIA 是双向的，去程见到 `59.43` 就是很强的证据**；但只有回程 GIA 的
  > （GT / 单向优化）去程可能走 163，所以这条**能正证、不能反证**。
  > 嫌命令麻烦就用 itdog.cn / ping.pe（网页，能一次多地测）或商家自己的
  > Looking Glass。

1. **IP 画像** —— ASN / 宣告前缀 / 注册地，以及 `hosting`(机房) / `proxy`(代理) /
   `mobile` 三个标记。`proxy` 为真基本就是纯净度差；`hosting` 为真是 VPS 的常态，
   但流媒体和风控会更容易拦。
2. **三网回程路由** —— 三网 × **北京/上海/莆田/深圳/南宁/成都/西安/武汉** 8 城 =
   **24 个点**做 traceroute，**逐跳查真实 ASN**（走 Team Cymru 的 DNS whois，免密钥）
   判断走的哪条骨干：CN2 / 163 / 联通 9929 / 联通 169 / 移动 CMIN2 / 移动 CMI / CMNET。
   **并发跑**约 2 分钟，只出判定不列逐跳（24×30 跳会刷屏）。结果按运营商分组、
   用 `●`(优质) `○`(普通) 高亮，末尾给每家一行小结（优质/普通各几个点、哪些城市）。
   - 判定看的是**长途段**——把流量从境外拉回中国的那一段骨干，它决定延迟和拥塞。
     一台「三网回程 CN2 GIA」的机器，去联通、去移动的长途段**也是 `59.43`**，
     这正是它卖的东西，不是 bug。
   - 长途段的挑法：**优质骨干出现在路径的任何位置就算优质**，不是「第一个骨干跳」。
     实测踩过：DMIT LA 的路径里，进 `59.43` 之前还有一跳属于 `AS4134`（中国电信在
     美国那侧的接入），按「第一个」取就把整条 CN2 GIA 判成了「163 普通」——24 个点
     一个优质都没有，而落地那列还明晃晃写着 `→ 电信 CN2`，自相矛盾。
     没有优质骨干时，普通骨干取**第一次出现**（取最后一次会被落地网盖掉），
     同为普通时优先目标运营商自己的骨干。
   - **落地**进了哪家的网单独列在 `→` 后面（`→ 联通 169`、`→ 移动 CMNET`），
     不参与档次判定。移动的落地必然是 `CMNET (AS9808)`（移动**国内**网），
     跟线路档次无关。
   - 这两件事混成一件翻过三次车：① 取第一个优质跳、安到目标运营商头上，输出
     「联通 → 电信 CN2」，读起来像「联通的骨干是 CN2」，是胡话；② 矫枉过正改成
     只认目标运营商自己的骨干，三网回程 GIA 的卖点被判没了；③ 改取「第一个能认出
     的骨干跳」，被 CN2 前面那跳 `AS4134` 骗了，全判成 163。现在两件事分开说。
   - **判定不对时别猜，把路径打出来**：`python3 /etc/bgpeer/vps-check.py --hops <IP>`
     列出逐跳 IP、延迟、ASN、宣告前缀、注册地和分类（`等级/归属/国际或落地`），
     末尾给「路径上的骨干」小结；目标是**中国 IP** 时才额外按三网各判一遍
     （目标在国外谈不上「回程走哪条骨干」）。上面那三次翻车都是靠截图反推路径
     造成的，而路径本来一条命令就能看清。
     这个模式在**任何机器上**都能跑，不限于 VPS——在你国内的电脑上跑，量到的
     就是「国内 → 目标」的**去程**，见上面「外部IP检测」那段。
   - 延迟取**最后一个有响应的跳**（≈到目的地 RTT），不是长途段入口那跳——
     入口跳只是刚进骨干，拿它比三家等于比谁家入口近，没意义。路径被截断时它是下限。
   - 判定只认**已知骨干**：目的地自己的省级接入 AS（如 AS4835 CHINANET-IDC-SN）不算
     骨干，否则会把真正的骨干判定盖掉。
3. **IP 黑名单** —— 10 个 DNSBL。
4. **常用服务可达性** —— Google / YouTube / ChatGPT / Netflix / Disney+ / GitHub 的 443 握手。

> **只测回程**：这里跑的是 VPS→中国。去程（中国→VPS）本机测不到，要在国内侧测——
> 三网的去程和回程经常走**不同**骨干，别拿回程结论去推去程。

> **不区分 CN2 GIA / GT**，这是故意的。两者都走 `59.43` 段，而 `59.43.0.0/16` 是 CN2 的
> 内部传输网、**不在 BGP 全局路由表里**（查不到 AS，实测 `59.43.0.1` 无结果），
> 细分只能靠一套没有权威出处的前缀表。与其给你一个「自信但可能错」的结论，不如把证据
> （59.43 的跳、跳数、延迟）摆出来。要定性用 nexttrace：
> `curl -sL nxtrace.org/nt | bash && nexttrace 219.141.136.12`

> **测试点不盲信**：24 个测试点都用 Cymru 实测校验过归属，跑之前还会再验一次——
> 注册地必须是 CN、AS 名字必须对得上那家运营商，对不上就标「目标存疑」跳过。
> 归属按 **AS 名称模式**判（`CHINANET` / `CHINA169` / `CMNET` …）而不是枚举 ASN：
> 省级子 AS 太多列不全，同一家还会冒出 `CHINANET-BACKBONE` / `CHINATELECOM-HUBEI-…` /
> `CHINA TELECOM` 好几种写法。（公认的「北京电信」测试 IP `219.141.136.12` 实际归属是
> AS4847 CNIX 而不是 AS4134，正是靠这套校验才没被当成 163。）

> **多源前缀取最长掩码**：一个 IP 可能落在多条 origin 记录里（同段被不同 AS 以不同掩码
> 宣告），Cymru 返回顺序还不固定——取第一条会导致同一个 IP 两次查出不同结果
> （实测 `202.103.24.68` 一会儿 AS4134`/18`、一会儿 AS137266`/20`）。按 BGP 语义取
> **最具体**的那条。

> **黑名单的「未知」不等于干净**：Spamhaus 这类会拒绝来自公共 DNS 的查询，而且拒绝方式是
> **返回空**而不是报错——直接当成「干净」就是假阴性。所以每个表都先用官方测试地址
> `127.0.0.2` 探活，列表不回话就标「未知」。
