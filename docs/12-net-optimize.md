# 12. 网络优化

一键调用本仓库的 `net-optimize.py`（BBR / QoS / 缓冲区等内核调优，Python 重构版，
所需依赖工具会自动安装），不用再手动复制命令。所有档位的底子都是 **BBR + fq 队列 + 按内存算的缓冲区**。三种模式：

1. **自适应智能算法+抢占带宽**（流量达 10MB/s 激活）——适合内存 <1G 的机器；
2. **自适应智能算法+抢占带宽**（默认 20MB/s 激活，**阈值可自定义**）——适合内存 2G 左右的机器；
   在阈值处**输入 `0` 即切到「纯暴力发包」模式**：固定 `fq` + 激进参数一直抢带宽、
   不切 cake、不起自适应守护，适合只要吞吐、不在乎游戏低延迟的场景；
3. **固定 cake 纯智能算法**（不切换）——适合高性能机器。

1 / 2 档的「按流量自动切换」（流量 ≥ 阈值切 fq 抢带宽、< 阈值切 cake / prio 游戏低延迟）由一个常驻守护进程做，
**4.5.17 起改成可选、默认关**：关着时出口固定用 `fq`（按流公平、按 BBR 的节奏发包），阈值只在打开后才用。
选 `7` **自适应切换（守护进程）**开 / 关——只改这一项，不重跑整套优化、不动 nginx / sing-box。

> 选 1 / 2 / 3 跑优化前会先问一句 **`确认执行？y 确认 / n 返回`**（默认否）——因为跑优化会重新应用
> 内核参数、期间可能短暂重启 nginx / sing-box，完全生效要重启一次；按错数字也能直接 `n` 退回，不会误跑。
> 跑完会问「是否立即重启」（默认否）：只认问出来以后打的 `y`——跑的过程中按到的键先丢掉（早按的 `y` 回车不会替你答），
> 手机终端误碰 Home / 方向键混进来的按键码也去掉，照样认得出 `y`（4.5.21 起）。

进菜单**顶部会显示当前档位**（如 `自适应+抢带宽 · 15MB/s 激活` / `自适应+抢带宽 · 10MB/s 激活 · 切换关` /
`固定 cake 纯智能算法` / `纯暴力发包（固定抢带宽，无智能算法）`），
对应的选项后面标 `← 当前`，一眼看出这台机器现在跑的是哪一档、阈值多少。档位状态从
`/etc/net-optimize/config`（模式、阈值、切换开关）读，卸载后自动回到「未优化」。

优化完（或任何时候）可选 `5` **网络优化状况**，一键检测当前优化状态（`net-optimize.py --check`）。

**保留端口跟着节点走**（4.5.18 起）：节点脚本把节点占的端口（两核心入站、CDN、订阅端口、nginx 本地口、hy2 跳跃段）
写成「节点画像」（`/etc/bgpeer/netprofile.json`，只有端口、只给 root 看），网络优化照单、连同本机其它服务
（OpenList / Emby / AdGuard / 改过的 SSH…）的端口一起从临时端口池摘掉——出站连接占不走，节点、容器重启时绑得上。
以前写死 15000-45000，池子外的（CDN 2053 / 8443、nginx 本地 8443-8445、自己指定的订阅端口、Emby 8096…）都漏了；
整段 15000-45000 照留（新协议从挑端口到真正绑上有几十秒空档）。装 / 删协议、CDN 增删、换订阅端口、进面板时
自动刷新这一项（只改一个内核参数，不重跑优化、不重启任何服务、不影响在播）；`5 网络优化状况` 里显示
`保留端口：已跟节点对上（节点端口 N 个 · 跳跃段 N 段 · 本机其它服务 N 个）`。
不想优化了选 `6` **卸载网络优化**（`--reset`）：清除全部优化配置（服务/内核参数/防火墙标记/
持久化规则），恢复系统默认，节点本身不受影响；建议卸载后重启一次。

选 `4` **换 BBRv3 内核（XanMod）**（`--xanmod`）：原厂内核只有 BBRv1，XanMod 自带 v3（名字仍叫 `bbr`、默认就开）。
后面「当前」显示这台是 `BBRv3` / `已装好，重启后生效` / `原厂内核（BBRv1）`。

- **先查能不能换**：x86_64、不是容器（LXC / OpenVZ 跟宿主机共用内核）、Debian 12+ / Ubuntu 24.04+、
  没开 Secure Boot、磁盘够；CPU 档位自动认（v1 / v2 / v3，v4 用 v3 包），装错档位会开不了机。不合格一行说原因，什么都不改。
- 普通 VPS（DMIT、搬瓦工这类通用内核的）：一行提示 + 问一次、默认「否」；
  认出是谷歌云 / AWS / Azure / 甲骨文（自带专用内核，换了最容易开不了机）：**红色警告，要输入 `yes` 才装**，其他一律取消；装 MAIN 分支，没有就装 LTS（Debian 12 只有 LTS）。几分钟，装完一行 ✔。
  装的时候不让 needrestart 重启服务（依赖顺带升级库时它会重启 sing-box / nginx，正在看的片就断了）。
- **已经是 BBRv3 的**（XanMod 或别家 v3 内核）不再装，只把拥塞算法对成 `bbr`——「当前」显示
  `BBRv3 内核，在用 cubic` 时选它就修好。
- **不自动重启**：会再问一次（默认「否」）——重启会断开所有连接，正在看的片也会断。
  万一起不来，用服务商后台 VNC 在 GRUB 里选回原来的内核（原厂内核不删）。
- **会连 XanMod**：`dl.xanmod.org` 拿签名公钥、`deb.xanmod.org` 拿包，对方能看到这台 VPS 的 IP（跟 nginx 官方源一样）。
  软件源先试 https，不通才用 http；走 http 时路上看得出装的是 XanMod 内核，包有签名改不了。
- 重启后 `4 网络优化状况` 里显示 `bbr（v3）` 就是用上了。想换回原厂内核：GRUB 里选原来那个启动，
  再 `apt purge 'linux-xanmod*' 'linux-image-*xanmod*' 'linux-headers-*xanmod*'`，
  删掉 `/etc/apt/sources.list.d/xanmod-release.list`。

> **4.5.17 起的变化**（仓库主人 10/25 同意）——要生效得进菜单重跑一次 1 / 2 / 3：
> - **队列默认 `fq`**（原来 `fq_pie`；「抢带宽」原来 `pfifo_fast`）。服务端出口网卡几乎不是瓶颈，排队发生在跨境段和用户那头，
>   本机的拥塞队列管理基本触发不了；BBR 靠按瓶颈速率均匀发包，`fq` 能替它做、最省 CPU，还按流公平，多人并发互不拖累。
>   想用回 `fq_pie`：`ENABLE_FQ_PIE=1`。
>   4.5.19 起设队列前先把 `sch_fq` 模块加载上（模块编了、文件不在的 Ubuntu 内核补装 `linux-modules-extra`），
>   选定的队列 / BBR 模块写进 `/etc/modules-load.d/net-optimize-qdisc.conf` 开机就加载。
>   Ubuntu 22.04 及以前的精简版 kvm 内核（`uname -r` 以 `-kvm` 结尾）压根没编进 fq，BBR 也没有，装什么都没用——
>   跑优化和 `5 网络优化状况` 都会照实说「这台内核没有 fq、BBR，要用得换内核」。
>   多队列网卡的「当前队列」显示 `mq（每个队列 fq，共 N 个）`：mq 只是总管，下面每个队列挂的 fq 才是真干活的；
>   网卡上实际挂的不是 fq 时，`[3]` 那段会照实说（4.5.20 起）。
> - **加 `nf_conntrack_tcp_be_liberal=1`**：跨境链路乱序 / 重传多，conntrack 会把一部分合法的「窗口外」包误判丢掉，表现是偶发卡顿、掉速。
> - **去掉 MPTCP**（节点不建 MPTCP 连接、手机也基本不用，纯空转）和 **DSCP 打标**（标的方向不对、公网会清零；换成 fq 后也用不着）。
>   老版本留下的规则 / 文件，下次跑优化或重启时自动清掉，`5 网络优化状况` 里还有残留会提示。
>
> 4.5.4 及以前在原厂内核上可能选成 `cubic`（bbr 模块没加载，脚本看不到它）；跑一次本菜单的档位就改回 `bbr`。
>
> 优化脚本自带 SHA256 校验的自动更新（对照仓库里的 `SHA256SUMS`），每次执行都是最新版；
> 并且每月 1 号北京 03:05 自动把脚本本体更到最新（`--self-update`，只换文件、不重跑优化，不影响在播），
> 排在 03:10 nginx 月度升级前面、进排队器；自适应 QoS 守护进程在出口闲着时重启一下换成新版。
> 新版的调优参数不会自己写进系统，要进菜单重跑一次优化（不用重启服务器）。装好不进菜单的机器也能跟上修的 bug / 加的兜底。
> 也可单独运行：`python3 <(curl -fsSL https://raw.githubusercontent.com/bgpeer/nodekit/main/net-optimize.py)`
