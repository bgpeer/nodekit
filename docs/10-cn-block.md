# 10. 屏蔽中国域名和IP

在服务端路由里把 **CN 域名（geosite geolocation-cn）+ CN IP（geoip cn）** 走 reject，
白名单内的 CN 服务照常直连。逻辑独立在 `cn-block.py`，方便单独维护。

```
  1 屏蔽中国域名和IP        （已开则再选可关闭）
  2 放行白名单（作者名单 / 自定义名单）
  3 自定义放行名单脚本链接
  4 单条放行域名/IP（自己加，按后缀匹配含子域）
  5 立即更新（拉取最新放行名单/规则集并生效，不用等每天定时刷新）
  6 卸载（不想屏蔽了，直接清掉规则）
  0 退出
```

> **`4 单条放行域名/IP`**：`2`/`3` 的白名单是**整组规则集**放行（`bilibili`、`tencent` 这种 tag），
> 粒度太粗——想单独放行某一个域名或 IP 就用这个。
> - **域名按后缀匹配**：填 `example.com`，它**和它的所有子域**都放行；`notexample.com`、
>   `example.com.evil.net` **不会**误命中（已用 `sing-box rule-set match` 实测）。
> - **IP 支持单个或 CIDR、IPv4/IPv6**：`1.2.3.4`（自动补 `/32`）、`10.0.0.0/8`、`2001:db8::/32` 都行。
> - 输入很宽容：`*.qq.com`、`+.qq.com`、`.qq.com`、大写、结尾多余的点都会自动归一；
>   中文域名自动转 punycode。非法输入**爆红提示并跳过**，不影响同批其它条目。
> - 添加/删除支持**逗号分隔批量**（删除还支持 `a` 全部）；已开启屏蔽时改完**立即重新注入生效**，
>   未开启则先存着、开启时自动带上。
> - 实现上用 sing-box 的 **inline rule_set**（tag 同样以 `cnblk-` 开头），复用既有的清理逻辑，
>   反复增删**不会重复注入**；没有条目时整个跳过，不会留下空壳（空数组会被 sing-box 判为非法配置）。
> - 规则顺序：**单条放行 → 规则集白名单 → CN 域名拦 → CN IP 拦 → 你原有的规则**，放行永远在拦截之前。
>
> **也可以直接写死在脚本里**（想让所有机器都带上时用）——`cn-block.py` 顶部两个列表，
> **域名和 IP 分开写**，各自只按自己的类型校验，不做自动识别：
>
> ```python
> ALLOW_DOMAINS = [
>     "example.com",        # 后缀匹配：连同它的所有子域一起放行
> ]
> ALLOW_IPS = [
>     "1.2.3.4",            # 单个 IP，自动补成 /32
>     "10.0.0.0/8",         # CIDR
>     "2001:db8::/32",      # IPv6 也行
> ]
> ```
>
> 写错类型会**跳过并提示**（把 IP 写进 `ALLOW_DOMAINS` → 「这看着是 IP，请写到 IP 列表里」），
> 不会污染配置。两处来源会**合并去重**（`8.8.8.8` 与 `8.8.8.8/32`、`QQ.COM` 与 `*.qq.com` 都算同一条）。
>
> ⚠️ **必须改仓库里的 `cn-block.py`**：VPS 上的 `/etc/bgpeer/cn-block.py` 每次进菜单都会被重新
> 下载覆盖，在那里改无效。反过来，**菜单里加的存在 `/etc/bgpeer/cnblock.json`，更新脚本不会丢**——
> 只对本机生效的用菜单，要全网生效的写进仓库。

- 规则集用 sing-box **远程 srs**（`.srs` binary），挂 cron **每天北京时间 03:00 定点刷新**（服务器在任何时区都自动换算，有夏令时的地方冬夏都对）。
- **`4 立即更新`**：在仓库改了放行名单 / 规则集后不想等到 03:00，进来点一下即时生效——
  重读放行名单（作者名单随最新 `cn-block.py`、自定义名单从链接实时拉）+ 清 sing-box 规则集缓存
  强制重拉最新 `.srs`，重新注入。沿用注入的校验/回滚：拉不到就保持原状、不影响节点。
- 优先走 **jsDelivr 镜像**、回退 raw；临时拉不到的先注入、交给自动更新重拉；
  确认不存在（404）的才跳过。
- 注入后会确认 sing-box 正常启动，**万一起不来自动回滚**，绝不影响原本能用的节点。
- **自定义放行名单链接（菜单 3）——别人可以整套抄走改成自己的**：
  仓库里放了一份可直接复制的样板 [`whitelist-template.py`](https://github.com/bgpeer/nodekit/blob/main/whitelist-template.py)，
  抄到自己仓库改完，把链接填进菜单 3 即可（GitHub 文件页链接也行，会自动换成 raw）。样板里三个列表都支持：

  | 列表 | 作用 |
  | --- | --- |
  | `WHITELIST_TAGS` | 规则集整组放行（`bilibili`、`tencent` 这类 tag） |
  | `ALLOW_DOMAINS` | 单条域名放行（后缀匹配，含子域） |
  | `ALLOW_IPS` | 单条 IP / CIDR 放行（v4/v6） |

  向下兼容老格式：纯文本 tag 列表（每行一个）、`whitelist-inject.sh` 的 `WHITELIST_TAGS=(...)` bash 数组，
  甚至**直接指向 `cn-block.py` 本身**也能解析。

  > 🔒 **远端文件只解析、绝不执行**：用 `ast.parse` + `literal_eval` 取字面量，
  > 所以别人的名单里就算写了 `os.system(...)` 也不会被运行（已实测：恶意样本中的命令未执行、
  > 含函数调用的条目被忽略）。每一条还会逐个校验——非法 tag、把 IP 写进域名列表、
  > 打错的 IP 都会**跳过并提示**，不会污染配置。

  三处来源（脚本写死的 `ALLOW_*` + 链接里的 + 菜单加的）**合并去重**后一起注入。
  改完不用等每天 03:00，点菜单 `5 立即更新` 即时生效。
- 白名单按**域名**（geosite）放行：客户端需走远程 DNS 解析（本项目生成的订阅配置默认即是）；
  若客户端本地解析后以裸 IP 出站，仍会被 CN IP 规则拦截。

规则集来自 [`bgpeer/rules`](https://github.com/bgpeer/rules)，
配套的白名单注入脚本见 [`nodekit/cn-block.py`](https://github.com/bgpeer/nodekit/blob/main/cn-block.py)。
