# 4. 更换伪装域名

reality 协议靠**借用一个真实大站的域名(SNI)**来伪装——客户端和服务端两边都得填同一个借用目标（如 `www.microsoft.com`）。哪天这个站从你 VPS **连不通了**（线路问题 / 被墙 / Akamai 边缘变化），reality 的"回落到真站借证书"就打折、伪装变弱。以前只能重装换，现在这个菜单**不用重装**就能换：

```
更换伪装域名（reality 借用的 SNI 目标站）
  当前伪装域名: www.ibm.com
  连通性检测: 通 · TLS1.3 + h2 ✓        ← 从本机实连一下：能否连上 + 支不支持 TLS1.3/HTTP2
  1 更换（随机挑 / 手动输入）
  0 返回
```

- **进去先自检**：显示当前借用域名，并从你 VPS **实测连通性**（openssl 连目标:443，看 TLS1.3 + h2）。绿=通、红=不通并提示建议更换。
- **`1 更换`**：`1` 从内置大站池随机挑（自动避开当前）、`2` 手动输入。换之前**再测一遍新域名**，不理想会警告让你确认或重选。
- **一键改全**：确认后自动改 **sing-box + xray 两核心**的 reality 配置（`server_name`/`handshake`/`dest`/`serverNames`）、**sni-split 的 nginx 443 分流映射**（如启用）、保存的**分享链接**里的 `sni=`，再**刷新订阅**（保持 token、URL 不变）。客户端重拉订阅即生效，无需重装、无需重新导入。
- **带回滚**：任一核心配置校验不过 / nginx 校验不过 → **整体回滚、不重启**，能用的节点不会被改坏。只动 reality 类节点，域名类(ws/trojan)节点的 SNI 不受影响。
