# 4. 更换伪装域名

reality 协议靠**借用一个真实大站的域名(SNI)**来伪装——客户端和服务端两边都得填同一个借用目标（如 `www.microsoft.com`）。哪天这个站从你 VPS **连不通了**（线路问题 / 被墙 / Akamai 边缘变化），reality 的"回落到真站借证书"就打折、伪装变弱。以前只能重装换，现在这个菜单**不用重装**就能换：

```
更换伪装域名（reality 借用的 SNI 目标站）
  sing-box 伪装域名：www.ibm.com　通 · TLS1.3 h2
  xray 伪装域名：www.cisco.com　通 · TLS1.3 h2
  1. 换 sing-box 的（随机挑 / 手动输入）
  2. 换 xray 的（随机挑 / 手动输入）
  0. 返回
```

两个核心的 reality **各用一个伪装域名、各换各的**（SNI 分流时 nginx 按伪装域名分流，两个一样就分不开）。
本机只有一个核心装了 reality 时只列那一项。

- **进去先自检**：每个核心的伪装域名后面写着从你 VPS **实测的连通性**（连目标:443，看 TLS1.3 + h2）。绿=通、红=不通，下面一行提示建议更换。
- **选一项再选怎么换**：`1` 从内置大站池随机挑（**避开当前的和另一个核心的**，只挑本机探得通的）、`2` 手动输入。
  手填的跟另一个核心的一样会**红字说重复、回到这一步重选**。换之前**再测一遍新域名**，不理想会警告让你确认或重选。
- **一键改全**：确认后只改**选中的那个核心**的 reality 配置（`server_name`/`handshake`/`dest`/`serverNames`）、
  保存的**分享链接**里它那些节点的 `sni=`，SNI 分流开着时**按两个核心当前的配置重建 nginx 分流表**，再**刷新订阅**（保持 token、URL 不变）。
  另一个核心的节点一个字不动。xray 的 grpc / xhttp 挂在 reality 入口后面的，链接跟着入口一起改。客户端重拉订阅即生效，无需重装、无需重新导入。
- **带回滚**：任一核心配置校验不过 / nginx 校验不过 → **整体回滚、不重启**，能用的节点不会被改坏。只动 reality 类节点，域名类(ws/trojan)节点的 SNI 不受影响。
- **抗量子签名跟着新站走**（只有 xray 内核的 reality 节点有这项）：新站够格就开、不够格就关，链接里的 `pqv=` 一起改（够格的条件见[安装篇](01-install.md#伪装--加密建议)）。换伪装域名本来就要客户端重拉订阅，这项不额外添麻烦。
