# nodekit · bgpeer 一键脚本

sing-box + xray 双核心、多协议一键部署，自动生成 **mihomo / sing-box / Shadowrocket** 三种订阅，
并可一键屏蔽中国域名/IP（白名单放行）。参考 mack-a/v2ray-agent 的协议组合用 Python 重写，装完直接给客户端一条订阅链接即可。

> ⚠️ 仅供个人学习与合法用途，使用前请阅读文末[免责声明](##免责声明)。

---
**执行代码前请先把域名拖管到CF绑定VPS的IP，不开小黄云，用域名安装效果更好**
## 👇一键安装代码

```bash
curl -sL https://raw.githubusercontent.com/bgpeer/nodekit/main/xy-installer.py -o /tmp/xy.py
sudo python3 /tmp/xy.py
```

若 `raw.githubusercontent.com` 被 GitHub 限流（HTTP 429），改用 jsDelivr 镜像（基本不会限流）：

```bash
curl -sL https://cdn.jsdelivr.net/gh/bgpeer/nodekit@main/xy-installer.py -o /tmp/xy.py
sudo python3 /tmp/xy.py
```

装过一次之后，以后直接敲 **`bgpeer`** 就能打开管理面板（内部已带镜像兜底，会尽量拉最新脚本）。

### 环境要求

- Debian / Ubuntu（systemd）
- root 权限
- Python 3
- 有域名走 acme 真证书更稳；无域名则自签证书 + 公网 IP 直连（域名需 A 记录直连指向本机）
- **证书自动续签**：走域名真证书时用 acme.sh 签发，acme.sh 会装每日 cron 自动续期（约 60 天一次），
  续期后自动重启 sing-box / xray（有 nginx 顺带 reload）使新证书生效，无需手动干预
- **内核自动更新**：安装后自动挂 cron，**每月北京时间 2 号凌晨 04:00** 把 sing-box / xray 更新到最新并重启一次
  （无新版则跳过）；也可随时进管理面板 **16 更新核心** 手动立即更新。日志在 `/var/log/bgpeer-coreupdate.log`
- **更新核心不怕 SSH 断**：更新的最后一步是重启核心，而很多人是**挂着本机代理管理这台机**的，重启会当场掐断 SSH。
  菜单 16 会把更新**派到独立会话里执行**（脱离控制终端，SIGHUP 打不到它），断开后仍在服务端跑完；前台只是实时跟随
  日志给你看进度，随时 Ctrl-C 或直接断开都不影响。重连后 `tail /var/log/bgpeer-coreupdate.log` 看结果
- **两个核心的取版本策略不同**（不是笔误，是刻意的）：**xray** 取全部 release 里**版本号最大的那个，包含被标为
  「预发行」的**——XTLS 从 `v26.6.1` 起把每个 release 都标成了预发行，而 GitHub 的 `/releases/latest` 按定义只返回
  非预发行版，只认它会**永远停在 `v26.3.27`**、每月的自动更新也推不动。注意预发行是 release 上的独立标志位、跟 tag
  名无关（xray 的 tag 一律是 `v26.7.28` 这种纯版本号，看 tag 名分辨不出来）。**sing-box** 则仍只认 `/releases/latest`
  的正式版：它 `1.13` 正式线和 `1.14.0-beta` 线**并行维护**，而 `1.14.0-beta.7` 的版本号大于 `1.13.16`，取最大会把人
  送上 beta 线、跨小版本换配置 schema，节点可能直接起不来
- **xray 26.7.11+ reality 兼容自愈**：xray 从 v26.7.11 起，reality 服务端**默认 `minClientVer=26.3.27`**，会
  **静默拒掉上报旧版本的客户端**（mihomo/Clash 系内核硬编码 reality 版本 `1.8.2`、sing-box、旧 xray）——表现为
  升级 xray 后 reality 节点客户端**连不上、也不报错**（全被丢进 fallback）。本脚本给 xray reality 入站显式写
  `minClientVer: "1.0.0"`（接受所有客户端）规避：**新装**即带；**老装**在「更新核心」或下次打开面板时**自动补上并重启 xray**
  （只在缺失时补一次，之后不再动）。sing-box 内核无此改动、不受影响。

## 支持的协议

| 核心 | 协议 |
|------|------|
| **sing-box** | vless-vision、vless-ws、vmess-ws、trojan、hy2(端口跳跃+salamander混淆)、reality-vision、reality-grpc、tuic、vmess-httpupgrade、anytls |
| **xray** | vless-reality-xhttp（sing-box 不支持 xhttp，由 xray 承载）、vless-reality-vision、vless-reality-grpc、vless-ws、vmess-ws、trojan |

可以只装 sing-box、只装 xray，或两个一起装。**端口/服务/配置都互不冲突**（两核心是独立进程、各绑各的随机端口、各写各的 config）。

> 两核心有几个同名协议（`vless-ws`/`vmess-ws`/`trojan`），sing-box 已能做且做得一样，xray 独有价值的只有 `vless-reality-xhttp`。所以**交互安装选「两个都装」时，xray 回车默认只装 `vless-reality-xhttp`**（sing-box 回车仍全装）；想让 xray 也全装,输 `0`/`all` 或点编号即可。只装 xray（选 2）时回车照常全装。
>
> 万一你让两核心装了同名协议（`vless-ws`/`vmess-ws`/`trojan`），为避免客户端订阅**重名报错**，会给它们**尾部各加一个小上标区分**：sing-box 那份加 `¹`、xray 那份加 `²`（如 `trojan¹` / `trojan²`）。只标撞名的这几个，其余不动；上标短，手机上也显示得下。端口/服务/配置本来就互不冲突。

## 管理面板

装完敲 `bgpeer` 进入：

```
  1. 安装（已装则问是否重装节点，y 重装 / n 返回）
  2. 节点链接 / 订阅
  3. 聚合节点链接（连机VPS合并多台VPS节点）
  4. 更换伪装域名（reality 借用的 SNI·带连通检测，不用重装）
  5. 多路复用开关 smux（只针对 ws / httpupgrade 协议）
  6. mihomo 配置
  7. sing-box 配置
  8. 小火箭配置
  9. CDN套用（域名+CF中转，延时较高，只能作备用）
  10. 屏蔽中国域名和IP（CN 域名+IP 拦截 / 白名单放行）
  11. BT/PT 下载屏蔽（防 VPS 被投诉封机）
  12. 网络优化（BBR/QoS 内核调优）
  13. 自建DNS（AdGuard Home·全设备DNS层去广告）
  14. GitHub中转（规则/图标走本机·默认开，可关）
  15. 更新脚本（不影响节点）
  16. 更新核心（sing-box / xray）
  17. 卸载
  0. 退出
```

> **`14 GitHub中转`**：订阅里的**规则集/图标链接**默认用第三方 `gh-proxy.com` 中转（国内直连 GitHub 常被墙）。
> 本项把它换成**本机自建中转**——用你自己的域名 `https://本机域名:订阅端口/<token>/gh/...`，不再依赖别人的服务。
> **默认开**（有域名+真证书时）。子菜单：`1` **本机中转写入配置（开/关）**、`2` **刷新中转 token**（防别人蹭，旧地址立即失效 + 自动刷新订阅；订阅端口不变、客户端自动更新即可）、`3` **刷新 token + 换端口**（更狠：连订阅端口一起换随机、自动避开节点端口；⚠ 换端口后订阅地址变，需重开防火墙 + 客户端重新导入订阅）。
> **认哪些链接**：以 **GitHub 原始文件主机名**为准（`raw.githubusercontent.com`、`gist.githubusercontent.com`、
> `objects.githubusercontent.com`），`gh-proxy.com` 前缀**可有可无**——很多人写模板不会加前缀，靠主机名识别才可靠。
> 三种写法都能自动改走本机中转：
> ```
> https://raw.githubusercontent.com/…              裸链接，自动识别
> https://gh-proxy.com/https://raw.github…         老写法，前缀会被整段替换
> https://随便哪个镜像/https://raw.github…          别人的镜像也整段替换（不会套娃）
> ```
> **不限仓库**：白名单按**主机**判定、不看是谁的仓库——别人自建中转转**他自己的**仓库同样可用。
> 裸的 `github.com` 项目页、`codeload` 的面板 zip **不会**被自动改（多为说明链接/大文件，误改无意义）；
> 确需中转就在模板里显式写代理前缀。改写只作用于**生成出来的订阅**，模板本身不动。
> - **带 token 防蹭**：中转地址带一段随机 token，别人不知道就用不了；token 文件存在 `/etc/bgpeer`（不在托管目录，不会被下载）。
> - **只白名单 GitHub**（`raw.githubusercontent.com`、`gist.github(usercontent).com`、`github.com`、`codeload.github.com`、
>   `objects.githubusercontent.com`），**绝不做成开放代理**；与订阅**同端口**（客户端本就从这端口拉订阅，无需额外放行）。
> - 用本机域名动态注入、**不写死公共模板**（模板里保留 `gh-proxy.com` 作占位/兜底，生成订阅时才替换成你的中转；别人的部署用别人的域名）。
> ⚠️ 单 IP：你 VPS 的 IP 被墙时中转会失效，但规则集客户端**有缓存、每天才更新**，不会立刻崩；无域名/自签则退回 `gh-proxy`。

面板顶部会显示**本机流量**。主菜单输 `t` 可按**机房账单口径**设置：每月流量重置日（如 DMIT
是 22 号）、月配额、计费方式（双向相加 / 单向取大），设置后顶部按「本周期已用 / 配额（剩多少，
几号重置）」显示，和机房面板同口径。vnstat 只统计装机之后的量，首次可把机房面板当前已用量填进
「校准」一次对齐，下个重置日起本机数据完整、自动不再需要校准。未设置时按自然月「本月/今日」
显示；vnstat 未装时先显示「开机以来」并自动后台安装。

### 更换伪装域名（菜单 4）

reality 协议靠**借用一个真实大站的域名(SNI)**来伪装——客户端和服务端两边都得填同一个借用目标（如 `www.microsoft.com`）。哪天这个站从你 VPS **连不通了**（线路问题 / 被墙 / Akamai 边缘变化），reality 的"回落到真站借证书"就打折、伪装变弱。以前只能重装换，现在这个菜单**不用重装**就能换：

```
更换伪装域名（reality 借用的 SNI 目标站）
  当前伪装域名: www.ibm.com
  连通性检测: 通 · TLS1.3 + h2 ✓        ← 从本机实连一下：能否连上 + 支不支持 TLS1.3/HTTP2
  1 更换（随机挑 / 手动输入）
  0 返回
```

- **进去先自检**：显示当前借用域名，并从你 VPS **实测连通性**（openssl 连目标:443，看 TLS1.3 + h2）。绿=通、红=不通并提示建议更换。
- **`1 更换`**：`1` 从内置大站池随机挑（自动避开当前）、`2` 手动输入。换之前**再测一遍新域名**，不理想会警告让你确认或重选。
- **一键改全**：确认后自动改 **sing-box + xray 两核心**的 reality 配置（`server_name`/`handshake`/`dest`/`serverNames`）、**sni-split 的 nginx 443 分流映射**（如启用）、保存的**分享链接**里的 `sni=`，再**刷新订阅**（保持 token、URL 不变）。客户端重拉订阅即生效，无需重装、无需重新导入。
- **带回滚**：任一核心配置校验不过 / nginx 校验不过 → **整体回滚、不重启**，能用的节点不会被改坏。只动 reality 类节点，域名类(ws/trojan)节点的 SNI 不受影响。

### CDN套用（菜单 9）

给"哪天 VPS 的 IP 被墙"备一条后路：菜单 9 每条起一个独立的 `xy-cdn-<n>` 实例、跑一个
**VLESS + WebSocket + TLS**（或所选协议）节点，套 Cloudflare 橙云中转——客户端连的是 **CF 的 IP**、
不是你 VPS 的真 IP，所以真 IP 被封了这条仍能用。与主节点完全隔离（独立服务/配置/证书），重装
主节点不受影响，也能单独卸载。

> 进菜单顶部就是简短说明。**执行前**：① 域名解析绑到本机 IP、开【橙色云】代理（必须橙云）；
> ② VPS 放行端口 2053/2083/2087/2096/8443（商用 VPS 一般全开放）；③ CF 的 SSL/TLS 模式选【Full 完全】。

- **可加多条**：`1 CDN节点安装` 里**协议可多选**（逗号分隔如 `1,3,4`、或 `a` 全选），一次把选中的都装上
  （共用你输入的那个域名、各占一个端口/服务）。已装过再进 `1` 会问 **y 清空重装 / a 追加新增 / 回车返回**。
  `2 查看` 上方列已配置节点、下方列全部备用链接；`4 卸载` 可选删某条、**多条（逗号分隔如 1,3）**或全部。
  CF 免费版可代理端口有限，最多 5 条。
- **不需要 Let's Encrypt**：CF 的 SSL 模式用 **Full（完全）**，源站自签证书即可（CF 不校验源站
  证书，客户端看到的是 CF 的有效证书）——省了 80 端口验证、证书续期一堆麻烦。
- **不需要 Origin Rule**：默认走 CF 可代理端口（2053/2083/2087/2096/8443，两端同口），避开主节点的 443/8443。
- 新增时可选**协议**（`1 VLESS+WS`·最稳 / `2 VLESS+XHTTP`·最快 / `3 VMess+WS` / `4 Trojan+WS`）、
  **核心**（sing-box / xray，XHTTP 入站仅 xray 支持会自动用 xray）、**名称前缀**（默认沿用安装前缀，
  如 🇯🇵；没设过可自定义；回车则 `CDN·协议`）。
- **写入订阅按客户端支持度自动筛选**：VLESS+WS / VMess+WS / Trojan+WS 三格式全支持；VLESS+XHTTP
  只有 mihomo 认，写入时 sing-box / 小火箭订阅自动跳过。无论哪种，**单条备用链接始终照常给出**
  （客户端自己怎么用不受订阅筛选影响）。
- 子菜单 `3 全部节点写入/移出订阅`（循环开关）：把全部 CDN 节点一键**并进三条订阅**并自动刷新
  （客户端拉一次即见）；再按一次即移出。**没装主节点也能生成订阅**（此时订阅只含 CDN 节点，但
  订阅地址走本机 IP，本机 IP 被墙则订阅地址也拉不到——节点本身经 CF 仍可用，改用单链接导入）。
- 前提：**一个域名 + 挂到 Cloudflare（免费版即可）**。

### 多机聚合 · 一条订阅汇总多台 VPS（菜单 3）

有 2~3 台 VPS 都装了节点，想把它们**汇总成一条订阅**、免去手动复制粘贴：

1. **每台机器**进「3 聚合节点链接」，**顶部**就显示这台自己的**节点链接地址**（`.links` 结尾，token 保护）；
2. 选一台当**主机**，进「3 聚合节点链接」→ `1 添加链接`，把其它机器顶部的那条 `.links` 地址粘进来；
   列表里每条后面实时显示连通性：通了 `✓`、不通显示红色状态码（`404`/`不通`）；
3. 主机进任意配置菜单点 **更新配置** → 自动拉本机 + 各成员机全部节点、去重、套模板、
   国家随机分组**跨机归类**，生成**一条聚合订阅**。客户端只导入主机这一条即可。

- 增删链接自动重排序号；**删除支持多选**（逗号分隔如 `1,3`、或 `a` 全部）；生成时**拉不到的成员自动忽略**（不影响其它机器）。
- **同名自动区分**：两台用相同前缀+相同协议时节点会重名（如两台都 `🇯🇵vless-vision`），
  mihomo/sing-box 不许重名，聚合时**只给撞名的加小上标** `¹²³`（→ `¹🇯🇵vless-vision`、
  `²🇯🇵vless-vision`），没撞的保持原样；旗子还在，国家随机分组照常归类。
- **links 链接可刷新（防泄露）**：`.links` 地址带 token，泄露了别人能直接拉你的节点。
  菜单里 `3 刷新本机 links 链接` 可随时换 token、旧地址立即失效；**重装换节点也会一起换**
  （和订阅一样）。换过之后，聚合了本机的主机会显示红色 `404`，重新复制新地址粘一次即可。
- 聚合后会把**各 VPS 都写进「直连」规则**（**有域名的用域名、没域名的用 IP**，配置里不落地裸 IP），
  你挂着聚合代理管理任意一台，管理流量都走直连不断线。<br>
  ⚠️ 用域名时直连规则匹配的是**域名**，所以挂着代理管理请 **SSH 到域名**（`ssh root@你的域名`）才会命中直连；
  直接 SSH 到裸 IP 不走这条规则（想彻底不断线要么 SSH 域名、要么管理时关代理）。

> **关于「改配置会重启核心、可能掐断 SSH」**：安装、smux 开关、BT 屏蔽、屏蔽中国域名、
> 更新核心等操作都会重启 sing-box/xray；若你正挂着这台机器的代理来 SSH 管理，重启会掐断隧道。
> 脚本已经做了三重保护，**单台 VPS 也不会被锁死**：
> 1. **改配置先校验、坏了自动回滚**（`sing-box check` / `xray -test` 不过就还原、绝不重启），
>    所以一个坏配置永远不会把你唯一的回程路弄没；
> 2. **状态先落盘、再后台异步重启**（`--no-block`），即便 SSH 断了操作也已在服务端完成，重连即最新；
> 3. **订阅里自动加一条「本机 IP 直连」规则**（mihomo/sing-box/小火箭都注入），
>    这样你挂着本机代理时，SSH 到这台 VPS 走**直连不进代理**，重启核心根本不断你。
> 客户端拉一次新订阅即生效。仍嫌麻烦的话，直连管理（管理时关代理）最省事。

### BT/PT 下载屏蔽（菜单 11）

装好后随时开/关,不用重装、不动节点。菜单里 `1` 循环切换。开启后服务端识别到 BT/PT
流量即 **reject**,防止有人用你的 VPS 挂 BT 下载、招来机房投诉封机:

- **sing-box**:路由加 `sniff` + `protocol: bittorrent → reject`,和「屏蔽中国域名/IP」的规则**互不覆盖**(各自只增删自己那几条)。
- **xray**:入站开安全嗅探(`routeOnly`)+ 路由 `bittorrent → block`;**vision 流入站自动跳过**(在它上面开嗅探会干扰,故不动)。
- best-effort:大部分 BT 会被拦,但 vision 流可能漏一小部分——这是协议特性,mack-a 同款限制。
- 开关状态记在 `bt.json`,重装节点会自动重新注入,不用再点一次。

### 网络优化（菜单 12）

一键调用本仓库的 `net-optimize.py`（BBR / QoS / 缓冲区等内核调优，Python 重构版，
所需依赖工具会自动安装），不用再手动复制命令。三种模式：

1. **自适应智能算法+抢占带宽**（流量达 10MB/s 激活）——适合内存 <1G 的机器；
2. **自适应智能算法+抢占带宽**（默认 20MB/s 激活，**阈值可自定义**）——适合内存 2G 左右的机器；
   在阈值处**输入 `0` 即切到「纯暴力发包」模式**：固定 `pfifo_fast` 一直抢带宽、不跑智能算法、
   不切 cake、不起自适应守护，适合只要吞吐、不在乎游戏低延迟的场景；
3. **固定 cake 纯智能算法**（不切换）——适合高性能机器。

进菜单**顶部会显示当前档位**（如 `自适应+抢带宽 · 15MB/s 激活` / `固定 cake 纯智能算法` /
`纯暴力发包（固定抢带宽，无智能算法）`），
对应的选项后面标 `← 当前`，一眼看出这台机器现在跑的是哪一档、阈值多少。档位状态从
`/etc/net-optimize/config`（模式）和 `adaptive-qos.conf`（阈值）读，卸载后自动回到「未优化」。

优化完（或任何时候）可选 `4` **网络优化状况**，一键检测当前优化状态（`net-optimize.py --check`）。
不想优化了选 `5` **卸载网络优化**（`--reset`）：清除全部优化配置（服务/内核参数/防火墙标记/
持久化规则），恢复系统默认，节点本身不受影响；建议卸载后重启一次。

> 优化脚本自带 SHA256 校验的自动更新（对照仓库里的 `SHA256SUMS`），每次执行都是最新版。
> 也可单独运行：`python3 <(curl -fsSL https://raw.githubusercontent.com/bgpeer/nodekit/main/net-optimize.py)`

### 去广告 DNS · AdGuard Home（菜单 13）

给**没挂代理的设备**做 DNS 层去广告（挂代理的设备本来就靠订阅里的 `reject` 规则集拦广告，这个补的是「不挂代理」的场景）：智能电视、盒子、IoT、路由器这些**装不了代理客户端**的，或者**安卓「专用 DNS」全系统**去广告。逻辑独立在 `adguard-dns.py`，与 sing-box/xray/节点互不影响，可单独卸载。

```
  1 安装（装 AdGuard Home + 起服务，之后网页后台点几下完成设置）
  2 卸载（彻底移除，不动节点；若写过订阅会自动从订阅撤掉自建DNS并刷新）
  3 查看状态 / 设备怎么设置
  4 腾出 53 端口（被 systemd-resolved 占用时用）
  5 改后台端口（随机 2000-5000 / 自定义，防扫描；带回滚）
  6 把自建DNS写入订阅配置（开/关：第一次写入·再点移除，自动刷新）
  7 自检（服务/端口/证书/解析/访问控制 一次查清，只读不改）
```
> **`7 自检`**：**只读**，一次查清六项——① 服务在不在跑 ② 53/DoT/DoH/后台端口各由谁监听
> ③ 加密设置里的服务器名跟域名对不对、**证书还有几天到期** ④ 本机直连做**真实解析测试**
> （明文 53 / DoT / DoH 各发一次真查询，并顺带验广告有没有真拦住）⑤ **访问控制有没有限 IP**
> ⑥ 本机 ufw/firewalld 状态。最后汇总成一份「要处理的事」清单。
> **为什么要有它**：安卓「私人 DNS」是**严格模式**——填了主机名就只用这一台 DoT、**没有任何回落**，
> 它一挂手机整机所有 App 立刻解析失败（`No address associated with hostname`），
> 连节点域名都解析不出来、想靠代理自救都不行。最常见的坑是**访问控制里填了「允许的客户端」**：
> 手机从 WiFi 切到 4G 出口 IP 一变就被拒 → 整机断网。自检直接把这条标红。
> （真被锁死时的自救：手机 设置 → 网络和互联网 → 私人DNS → 改「关闭」或「自动」，解析立刻恢复。）
> **`6 把自建DNS写入订阅配置`**：开关（循环）——把本机 AdGuard 的 DoH（`https://本机域名:DoH端口/dns-query`，
> 端口从 AdGuardHome.yaml 读、默认 10443）**动态写进订阅配置的 DNS**（用本机域名、不写死在公共模板里）。
> 只写 **mihomo / 小火箭**：把自建 DoH 放 DNS 列表**最前当主用、原有留兜底**——AdGuard 没通会**自动回落**到原 DNS，
> 不会断解析。mihomo 写两处：`nameserver`（默认解析）+ `global-dns` 锚点（`nameserver-policy` 里所有走代理的
> 域名组 `*global-dns` 共用它，改锚点一行 17 个组全带上）；**`cn-dns` 组不动**——国内域名该走国内解析拿就近 CDN，
> 用境外自建 DNS 反而慢。**sing-box 的 DNS 无列表回落机制，强改易断解析，故不写入。** 第一次点写入、再点问是否移除，
> 执行后自动刷新订阅（不换 token），客户端重拉一次即生效。前提：AdGuard 已开加密(DoH)、防火墙放行 DoH 端口。
> **卸载联动**：`2 卸载` 时如果之前用过本项写入订阅，会**自动把自建 DoH 从订阅里撤掉并刷新**（不换 token），避免订阅里留着指向已卸载 AGH 的死 DoH；客户端重拉即恢复原 DNS（mihomo/小火箭本就带回落，撤不撤都不会断解析，撤掉更干净）。全量卸载（主菜单 `17`）则整条订阅一起删，无需刷新。
> **`5 改后台端口`**：把网页后台的 3000 改成随机 2000-5000（或自定义），避免固定端口被批量扫描。
> 只改后台管理端口——**DNS 端口是协议固定的动不了**（53 明文、853 DoT/安卓专用DNS、10443 DoH）。
> 带校验回滚：改完 AGH 没在新端口正常起来就自动回滚，不会把你锁在后台外面。改完记得防火墙放行新端口、关掉旧的。

- **一键装好起服务**：菜单 1 用 AdGuard Home 官方脚本装到 `/opt/AdGuardHome` 并注册服务。AdGuard Home 是**网页后台管理**的软件，装完打开 `http://VPS_IP:3000` 按向导设管理员密码即可（**广告过滤默认就开**）。
- **设备怎么用**：
  - **电视/盒子/IoT/路由器**：DNS 填 **VPS 的 IP**（明文，需放行 `53` UDP/TCP）。
  - **安卓手机「专用 DNS」（全系统加密，推荐）**：网页后台 → 设置 → 加密设置，启用、服务器名填**你的域名**、
    证书指到脚本已有的 acme 证书（`/etc/ssl/sb/acme.crt` + `.key`）、DoT 端口 `853`、HTTPS/DoH 端口填 `10443`（不占 443）；
    然后手机 设置→网络→专用DNS→ 填**你的域名**，全系统 App 走去广告 DNS。
- **加密走 DoT(853)**：DoH 需要 443（被 reality/nginx 占了）故不用；DoT 走 853 独立端口，不影响现有节点。**需要域名 + 真证书**（安卓专用 DNS 才验得过）。
- **端口 53 冲突**：常被 `systemd-resolved` 占用——加密 DoT(853) 不受影响；要走明文 53 就用菜单 `4 腾出53端口`（关掉 resolved 的 53 桩监听，可逆）。
- **安全**：公网 DNS 有被拿去做 DDoS 放大的风险，AdGuard Home 默认带每客户端限速；优先用 DoT、别裸奔明文 53。
- **进后台优先用域名 HTTPS**：开了加密后，AGH 后台**同时挂在 `https://你的域名:10443/`**（和 DoH 同一个 HTTPS 端口——根路径 `/` 是后台、`/dns-query` 是 DoH），登录密码全程加密。别再用 `http://IP:端口` 明文登录（密码会明文过网）。AGH 本身**不支持 URL 加 token/密令路径**，后台靠「随机端口 + 账号密码 + HTTPS」三层防护即可；状态(3)/自检(7)/改端口(5) 检测到开了加密都会把这条 HTTPS 地址显示出来、并把明文入口标注出来。
- 主菜单 `17 卸载`（整体卸载）会**一并撤掉 AdGuard Home**（它的 DoT 依赖 acme 证书，证书随整体卸载删除）。

### 多路复用开关 smux（菜单 5）

装好后随时开/关 smux，不用重装、不动节点。菜单里 `1` 循环切换（显示当前状态，
`y` 确认 / `n` 返回）。执行后自动:改 sing-box ws 入站的 `multiplex` → 同步分享链接

或到各配置菜单点 **3 更新配置** 即可生效。只影响 ws/httpupgrade 类 sing-box 节点，
xray 承载的 ws、reality/vision/QUIC 等一概不动。

### 订阅（三格式）

装完为每种客户端各生成一条订阅链接（托管端口**每台机器首装时随机分配**——固定端口所有人一样
容易被按端口批量扫描识别，随机后和协议端口混在一起。平时换 token、更新脚本/配置端口都不动、
订阅 URL 稳定；**只有重装换节点时端口才随 token 一起换新**。升级上来的老安装沿用原端口，
订阅链接不变）：

| 客户端 | 格式 |
|--------|------|
| mihomo / Clash | `.yaml` |
| sing-box | `.json` |
| Shadowrocket（小火箭）| `.conf` |

**订阅走 HTTPS**：有域名 + acme 真证书时，订阅托管服务自动用真证书起 **HTTPS**
（`https://你的域名:订阅端口/...`），订阅内容不再明文过网。证书续期时订阅服务同步重启、
不会拿旧证书。**无域名 / 自签**时仍是明文 HTTP（自签 TLS 客户端会拒，故不强开）——
想要 HTTPS 订阅就给个域名。

每种格式的配置模板都在本仓库里，节点参数由服务端实时注入到模板锚点，重装换节点也会自动更新。
详见下面的 [自定义模板 & 锚点](#自定义模板--锚点)。

### 每个配置菜单（5 / 6 / 7）里可以

- **修改配置**：编辑器直接改成品配置文件
- **修改订阅**：查看当前订阅 / 换 token（换链接不动配置）
- **更新配置**：用作者模板或**自定义模板**重新生成。会**先校验再生效**：成功显示
  `✅ 更新成功`；若模板改坏了（JSON/YAML 语法错、缺关键段）显示 `❌ 更新失败` 并打印
  具体语法错误，**自动保留原来能用的配置、不会把坏的推给客户端**。
  （只验语法，不用服务器内核对客户端配置做语义校验——避免客户端/服务器内核版本不同、
  模板里 `dns.optimistic` 等字段被误判失败。）
- **自定义模板链接（添加 / 更换 / 删除）**：把你放在 gist / GitHub 上、占位符一致的模板拉进来映射节点。
  已设过链接再进来会给 **`1 更换` / `2 删除` / `0 返回`**；删除即改回作者模板，并可当场用作者模板重新生成一次配置

> 重装节点会刷新三条订阅的 token；只更新脚本或更新配置不换 token。
> sing-box 订阅按模板的**紧凑格式**输出（每个节点/策略组/规则一行一个），不会展开成逐行大 JSON。

### 屏蔽中国域名和IP（菜单 10）

在服务端路由里把 **CN 域名（geosite geolocation-cn）+ CN IP（geoip cn）** 走 reject，
白名单内的 CN 服务照常直连。逻辑独立在 `cn-block.py`，方便单独维护。

```
  1 屏蔽中国域名和IP        （已开则再选可关闭）
  2 放行白名单（作者名单 / 自定义名单）
  3 自定义放行名单脚本链接
  4 单条放行域名/IP（自己加，按后缀匹配含子域）
  5 立即更新（拉取最新放行名单/规则集并生效，不用等每天定时刷新）
  6 卸载（不想屏蔽了，直接清掉规则）
  0 退出
```

> **`4 单条放行域名/IP`**：`2`/`3` 的白名单是**整组规则集**放行（`bilibili`、`tencent` 这种 tag），
> 粒度太粗——想单独放行某一个域名或 IP 就用这个。
> - **域名按后缀匹配**：填 `example.com`，它**和它的所有子域**都放行；`notexample.com`、
>   `example.com.evil.net` **不会**误命中（已用 `sing-box rule-set match` 实测）。
> - **IP 支持单个或 CIDR、IPv4/IPv6**：`1.2.3.4`（自动补 `/32`）、`10.0.0.0/8`、`2001:db8::/32` 都行。
> - 输入很宽容：`*.qq.com`、`+.qq.com`、`.qq.com`、大写、结尾多余的点都会自动归一；
>   中文域名自动转 punycode。非法输入**爆红提示并跳过**，不影响同批其它条目。
> - 添加/删除支持**逗号分隔批量**（删除还支持 `a` 全部）；已开启屏蔽时改完**立即重新注入生效**，
>   未开启则先存着、开启时自动带上。
> - 实现上用 sing-box 的 **inline rule_set**（tag 同样以 `cnblk-` 开头），复用既有的清理逻辑，
>   反复增删**不会重复注入**；没有条目时整个跳过，不会留下空壳（空数组会被 sing-box 判为非法配置）。
> - 规则顺序：**单条放行 → 规则集白名单 → CN 域名拦 → CN IP 拦 → 你原有的规则**，放行永远在拦截之前。
>
> **也可以直接写死在脚本里**（想让所有机器都带上时用）——`cn-block.py` 顶部两个列表，
> **域名和 IP 分开写**，各自只按自己的类型校验，不做自动识别：
>
> ```python
> ALLOW_DOMAINS = [
>     "example.com",        # 后缀匹配：连同它的所有子域一起放行
> ]
> ALLOW_IPS = [
>     "1.2.3.4",            # 单个 IP，自动补成 /32
>     "10.0.0.0/8",         # CIDR
>     "2001:db8::/32",      # IPv6 也行
> ]
> ```
>
> 写错类型会**跳过并提示**（把 IP 写进 `ALLOW_DOMAINS` → 「这看着是 IP，请写到 IP 列表里」），
> 不会污染配置。两处来源会**合并去重**（`8.8.8.8` 与 `8.8.8.8/32`、`QQ.COM` 与 `*.qq.com` 都算同一条）。
>
> ⚠️ **必须改仓库里的 `cn-block.py`**：VPS 上的 `/etc/bgpeer/cn-block.py` 每次进菜单都会被重新
> 下载覆盖，在那里改无效。反过来，**菜单里加的存在 `/etc/bgpeer/cnblock.json`，更新脚本不会丢**——
> 只对本机生效的用菜单，要全网生效的写进仓库。

- 规则集用 sing-box **远程 srs**（`.srs` binary），挂 cron **每天北京时间 03:00 定点刷新**（UTC 19:00）。
- **`4 立即更新`**：在仓库改了放行名单 / 规则集后不想等到 03:00，进来点一下即时生效——
  重读放行名单（作者名单随最新 `cn-block.py`、自定义名单从链接实时拉）+ 清 sing-box 规则集缓存
  强制重拉最新 `.srs`，重新注入。沿用注入的校验/回滚：拉不到就保持原状、不影响节点。
- 优先走 **jsDelivr 镜像**、回退 raw；临时拉不到的先注入、交给自动更新重拉；
  确认不存在（404）的才跳过。
- 注入后会确认 sing-box 正常启动，**万一起不来自动回滚**，绝不影响原本能用的节点。
- **自定义放行名单链接（菜单 3）——别人可以整套抄走改成自己的**：
  仓库里放了一份可直接复制的样板 [`whitelist-template.py`](https://github.com/bgpeer/nodekit/blob/main/whitelist-template.py)，
  抄到自己仓库改完，把 **raw 链接**填进菜单 3 即可。样板里三个列表都支持：

  | 列表 | 作用 |
  | --- | --- |
  | `WHITELIST_TAGS` | 规则集整组放行（`bilibili`、`tencent` 这类 tag） |
  | `ALLOW_DOMAINS` | 单条域名放行（后缀匹配，含子域） |
  | `ALLOW_IPS` | 单条 IP / CIDR 放行（v4/v6） |

  向下兼容老格式：纯文本 tag 列表（每行一个）、`whitelist-inject.sh` 的 `WHITELIST_TAGS=(...)` bash 数组，
  甚至**直接指向 `cn-block.py` 本身**也能解析。

  > 🔒 **远端文件只解析、绝不执行**：用 `ast.parse` + `literal_eval` 取字面量，
  > 所以别人的名单里就算写了 `os.system(...)` 也不会被运行（已实测：恶意样本中的命令未执行、
  > 含函数调用的条目被忽略）。每一条还会逐个校验——非法 tag、把 IP 写进域名列表、
  > 打错的 IP 都会**跳过并提示**，不会污染配置。

  三处来源（脚本写死的 `ALLOW_*` + 链接里的 + 菜单加的）**合并去重**后一起注入。
  改完不用等每天 03:00，点菜单 `5 立即更新` 即时生效。
- 白名单按**域名**（geosite）放行：客户端需走远程 DNS 解析（本项目生成的订阅配置默认即是）；
  若客户端本地解析后以裸 IP 出站，仍会被 CN IP 规则拦截。

规则集来自 [`bgpeer/rules`](https://github.com/bgpeer/rules)，
配套的白名单注入脚本见 [`nodekit/cn-block.py`](https://github.com/bgpeer/nodekit/blob/main/cn-block.py)。

## 自定义模板 & 锚点

你可以把**自己的配置模板**放到 gist / GitHub raw，脚本按锚点把节点和国家随机组注入进去。
好处：**既能在模板里手写自己的静态节点，又能把成品配置直接托管到服务器保存**；
本仓库的作者模板既是参考，也是首次搭建的人开箱即用的配置。

**三个作者模板（点开直接看）**：

| 客户端 | 模板文件 |
|--------|----------|
| mihomo / Clash | [`sub-template.yaml`](https://github.com/bgpeer/nodekit/blob/main/sub-template.yaml) |
| sing-box | [`subbox-template.json`](https://github.com/bgpeer/nodekit/blob/main/subbox-template.json) |
| Shadowrocket（小火箭）| [`shadowrocket-template.conf`](https://github.com/bgpeer/nodekit/blob/main/shadowrocket-template.conf) |

### 三个锚点（三格式同名，各按自己语法渲染）

| 锚点 | 作用 | 展开成 | 放哪 |
|------|------|--------|------|
| `__XY_NODES__` | **建节点** | 你 VPS 的真实节点 | 独占一行（mihomo `proxies:` 段 / sing-box `outbounds` / 小火箭 `[Proxy]` 段） |
| `__XY_GROUPS__` | **建国家策略组** | 各国 url-test 随机组的**定义** | 独占一行（mihomo `proxy-groups:` 段 / sing-box `outbounds` / 小火箭 `[Proxy Group]` 段） |
| `__XY_NAMES__` | **引用国家组名** | 建好的国家组**名字清单** | **写在列表行内**（主选择组 / 服务组的 proxies·outbounds 里，可放多处） |

> 顺序依赖：必须先有 `__XY_GROUPS__` 把组**造出来**，`__XY_NAMES__` 才有组名可引用；
> 只写 `__XY_NAMES__` 不写 `__XY_GROUPS__` → 引用了不存在的组 → 客户端报错/起不来。

### 国家随机分组是怎么来的

- 脚本扫描**全部节点名**（`__XY_NODES__` 注入的订阅节点 **＋** 你手写进模板的静态节点），
  按**旗子 / 关键词**（如 `🇯🇵`、`JP`、`日本`、`Tokyo`）归国；
- 某国**≥2 个**节点才建该国随机组（`1` 个不建）；剩下没归入任何国家的进「🎲其他随机」；
  `🇺🇲` 自动归一到 `🇺🇸`；一个国家都没有则整段不建。
- **mihomo** 用 `filter`+`include-all`：客户端按正则**自动收拢**匹配节点（连你机场订阅合并进来的同国节点也会进组）；
- **sing-box / 小火箭** 没有 filter：由脚本**算好每国成员显式列进去**。

#### 想在模板里自己写国家组？同名即接管（**三种格式都一样**）

脚本生成前会先扫一遍模板里已有的组名，**同名的就不再自动生成**，让你写的那个说了算：

| 你在模板里写 | 脚本行为 |
|---|---|
| 什么都不写 | 照常生成 `🇺🇸美国随机`、`🇯🇵日本随机` 等 |
| `🇺🇸美国自动`（**不同名**） | 两个**并存**——你的 `🇺🇸美国自动` + 脚本的 `🇺🇸美国随机`，各管各的 |
| `🇺🇸美国随机`（**同名**） | **不再生成**，样式完全由你定；其他国家组不受影响 |

各格式扫描的位置：**mihomo** 扫 `proxy-groups:` 段；**sing-box** 扫 `outbounds` 里所有 `tag`；
**小火箭** 扫 `[Proxy Group]` 段。同名被跳过时，那个名字**仍会由 `__XY_NAMES__` 展开**——
引用会指向你模板里的同名组，位置和作用跟原来一致，不用额外改什么。

> **不同名时要注意**：`__XY_NAMES__` 只展开**脚本生成的**组名。你自己写的那个要出现在别的策略组里，
> 得**手动加进对应的列表**（mihomo 的 `proxies:` / sing-box 的 `outbounds` / 小火箭的组定义行）。

为什么要这样——重名不是「以某一个为准」的软覆盖，是**硬失败、客户端直接起不来**：

```
mihomo    ProxyGroup 🇺🇸美国随机: duplicate group name          → 配置加载失败
sing-box  FATAL decode config: duplicate outbound/endpoint tag  → 配置解析失败
```

### 放置规则（照着作者模板抄最稳）

- **块锚点**（`__XY_NODES__` / `__XY_GROUPS__`）：**各占一行**。顶格或缩进都行（生成器会整行替换、自带缩进，缩进不会把 YAML 弄乱）。
- **行内锚点**（`__XY_NAMES__`）：写在 `[...]` 列表里。例：
  - mihomo：`proxies: ["♻️全部随机"__XY_NAMES__]` → `["♻️全部随机","🇯🇵日本随机","🇺🇸美国随机"]`
  - sing-box：`"outbounds": ["♻️随机", "__XY_NAMES__:.*"]`
- **只 sing-box** 的 `__XY_NAMES__` 可带正则后缀：
  - `__XY_NAMES__:.*` = 国家组名 **＋** 全部节点名；
  - 裸 `__XY_NAMES__` = **只**国家组名。
  - 老锚点 `__PATTERN__:.*`（只全部节点名）生成器仍兼容，但作者模板已统一用 `__XY_NAMES__`。

> 机制核心：**检测到锚点才展开，漏写不报错、只是不生成**。就算忘了写 `__XY_NODES__`，也只是不注入节点、模板原样拉上来，不会报错。

### 怎么用自定义模板

1. 进对应配置菜单（**5** mihomo / **6** sing-box / **7** 小火箭）→ **添加自定义模板链接**（填你 gist / GitHub raw 地址）；
2. 再选 **更新配置 → 自定义模板** 重新生成（不动节点、不换订阅 token）。

> ⚠️ **链接必须是 raw 直链**：在 GitHub 打开你的模板文件，点右上角 **Raw** 按钮，复制那时地址栏里的
> 链接（`https://raw.githubusercontent.com/...` 开头）；gist 同理也点 **Raw**。
> 浏览器里看文件时的普通分享链接（`https://github.com/.../blob/...`）返回的是**整个网页**（HTML），
> 不是模板文件内容，粘它进去点更新配置会报 `❌ 语法错误`。
>
> 更新配置每次都**实时重新拉取**你模板的最新版；GitHub raw 有约 5 分钟 CDN 缓存，改完模板等一两分钟再点更新。

## 命令行用法（非交互）

也可以不进菜单，直接带参数安装：

```bash
# 装全部协议
sudo python3 xy-installer.py --sb all --xray all

# 指定协议 + 域名真证书
sudo python3 xy-installer.py --sb reality-vision,hy2,tuic --xray vless-reality-xhttp \
     --domain a.example.com --email me@example.com

# nginx 前置（443 伪装站 + webroot 证书，ws 类藏 443），需域名
sudo python3 xy-installer.py --sb all --domain a.example.com --nginx
```

常用参数：`--sb` / `--xray`（协议，逗号分隔或 `all`）、`--domain`、`--email`、
`--sni`（reality 借用目标站，**不填=从内置大厂池随机挑一个**，避免所有人挤在同一个 SNI）、`--prefix`（节点名前缀）、
`--hy2-ports`（hy2 端口跳跃范围，默认 `30000-31000`；填 `off` 关闭跳跃、走单端口）、`--nginx`、
`--no-reality-443`（默认会把主力 reality 绑 443 抗封端口，加此参数则不绑）、
`--yes`（检测到 mack-a 等现有安装直接接管）。

## 伪装 / 加密建议

装机时脚本会自动做两项检查，帮你把伪装做扎实（都只提示、不阻断安装）：

- **Reality SNI 随机池 + 预检**：安装时**默认从内置的大厂/技术站池里随机挑一个**当 reality 借用目标
  （cisco/oracle/python/intel/dell/苹果CDN/微软 等 21 个，实测 TLS1.3+h2+X25519、国内可达、不套乱 CDN）——
  避免所有人都按回车挤在同一个 SNI 上被针对。想指定就 `--sni 域名` 或交互里输入。选了 reality 系列协议时，
  装前还会探测借用目标是否**可达 + 支持 TLS1.3 + HTTP/2**，不合格给黄色警告并建议换站。
  > ⚠️ 伪装目标要用**国内可达的国外大站**：别用被墙的站（google/youtube 等），更**不能用国内域名**
  > （国外 IP 配国内 SNI = IP 与 SNI 极度不匹配，最容易被识别）。
- **无域名自签提示**：不给域名时，依赖证书的 TLS 协议（vless-vision / trojan / ws 家族 / anytls）
  只能走**自签证书 + 客户端 `allowInsecure`**——内容仍加密（各协议有自己的密码/UUID），
  但失去证书校验、且自签本身是明显特征。**想要更强伪装：优先用 `reality-*` 系列**
  （借真站证书，无需域名、无 insecure），或补一个域名走 acme 真证书。
  hy2 / tuic 用自签是行业常规，无需担心。

订阅还带两项客户端增强（服务端已同步支持，均自动生成、无需手动配置）：

- **X25519MLKEM768 后量子密钥交换**（默认开）：`reality-*` 节点在 mihomo 订阅里带
  `reality-opts.support-x25519mlkem768: true`，握手改用抗量子的混合 KEX，也能进一步
  打散 reality 的 ClientHello 指纹。此字段由客户端主动发起，**旧核心会握手失败**，
  故脚本会**先检测本机核心版本**（sing-box ≥ 1.12.0、xray ≥ 25.5.16 才下发；
  版本读不出或过旧则自动省略，保连通性优先）。本脚本每月自动更新核心，正常无需担心。
- **smux 多路复用**（**默认关，安装时询问**）：仅 **ws / httpupgrade** 家族可两头开
  `h2mux`（mihomo `smux`、sing-box `multiplex`）。多条请求复用一条底层连接，
  **网页/小请求延迟更低、连接数更少更隐蔽**；但同一条 TCP 上的**队头阻塞**会让
  **大文件下载 / 测速 / 丢包重的跨境线**变慢，所以默认关——选了 ws 类节点时装机会问一句
  `y开启/n不开(回车=不开)`，命令行用 `--smux` 开启。
  vision / reality / grpc / QUIC(hy2、tuic) / anytls **一律不参与**（它们要么自带更优复用、
  要么与 xray `mux.cool` 不兼容），xray 承载的 ws 也不带该标记，避免两端复用协议不一致。

**伪装站可自替换**：`--nginx` 模式下 443 的伪装首页在 `/var/www/bgpeer/index.html`
（默认是一个「维护中」通用静态页，不是一眼假的 Apache 默认页）。你可以直接覆盖它换成自己的
真站内容，伪装效果更好。

### reality 绑 443（抗 GFW 封端口，默认开启）

xray 内核会警告 `REALITY: Listening on non-443 ports may get your IP blocked by the GFW`——
reality 跑在非 443 高端口，从国内长期用有被封 IP 的风险。为此脚本**默认把主力 reality
协议绑到 443**（优先 sing-box `reality-vision`）：

- 主动探测打你的 443 → sing-box 把握手转发到**借用的真站**（如 awsstatic），
  看到的是真站证书，和真访问该站无法区分——比任何本地伪装站都强。
- 端口随机化削弱"一排代理端口"的扫描指纹；reality 上 443 再消掉"非 443 易被封"的风险，两者互补。

与 nginx 前置的关系：reality 独占 443/TCP 时，**nginx 只保留 :80 用于 acme 证书续期**
（续期不会因此中断），ws 家族不再藏 443、改走各自端口的真证书；443 的"网站伪装"
由 reality 借用的真站接管。其余协议（trojan/tuic/anytls/vless-vision 等）留在随机端口作备用。

加 `--no-reality-443` 可关闭此行为（reality 回到随机端口、保留 nginx 443 前置）。

### SNI 分流（`--sni-split`，最强抗封锁，需域名 + reality-vision）

比 reality 直绑 443 更进一步：用 nginx `stream` + `ssl_preread` 在 443 **按 SNI 不解密分流**，
让 **reality + 网站 + ws 全部只用 443**，对外就是一个 HTTPS 网站：

- SNI = reality 借用域名（如 `s0.awsstatic.com`）→ 转发给本地 reality 端口；
- SNI = 你的真域名 / 默认 → 转发给本地 https（伪装站 + ws 反代）；
- hy2 仍走自己的 UDP 端口 + 跳跃（QUIC 与 nginx 的 443/TCP 不冲突）；
- 证书续期继续走 nginx `:80` webroot，不受影响。

安全兜底：改 `nginx.conf` **前先做 preflight**（装 `libnginx-mod-stream`，用测试配置跑 `nginx -t`），
探测不过就**自动退回 reality-443 直连**；正式写入若 `nginx -t` 不过则**整体回滚**并还原
`nginx.conf`，绝不把现有能用的 443 改坏。交互安装选了域名 + reality-vision 时会询问是否启用。

> v1 只把 sing-box `reality-vision` 放到 443 SNI 分流后面；其余 reality（xray xhttp 等）仍在随机端口。
> 这是较大的架构改动，务必在你自己的机器上实测（`openssl s_client` 打 443 分别用两个 SNI 验证走向 + 客户端逐协议连通）。

## 卸载

管理面板选 **16. 卸载**，进子菜单：

```
  1 卸载代理主体（网络优化保留）
  2 全部卸载（代理主体 + 网络优化，一次清干净、恢复系统默认）
  0 返回
```

- **代理主体**：sing-box / xray、订阅服务、证书、**AdGuard 自建DNS**（它的 DoT 依赖 acme 证书，
  证书随卸载删除，故一并撤掉）、CDN 套用节点、hy2 端口跳跃规则、nginx 前置块、`bgpeer` 命令、
  cn-block/内核更新等定时任务。
- **网络优化（BBR/QoS）**是独立模块（写在 `/etc/net-optimize`），选 `1` 会**保留**它；选 `2` 会先
  跑一遍 `net-optimize.py --reset` 再卸主体，把内核调优/服务/防火墙标记也清掉，恢复系统默认。
- 系统本身、SSH、你自己装的其它软件与网站一概不动。
